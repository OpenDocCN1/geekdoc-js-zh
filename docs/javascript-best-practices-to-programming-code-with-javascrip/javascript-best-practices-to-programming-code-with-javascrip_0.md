### 引号、大括号和圆括号不匹配
如果你经常这样做，有一个简单的方法可以避免这种错误。你只需要同时编写你的起始和结束元素即可！完成后，你就可以输入你想添加到代码中的元素了。这里有一个例子：

```javascript
var myString=" ";

}
}
```

- 第一行，你要在输入字符串值之前编写引号。这样你就不会忘记它们了。
- 在你的第二行，一旦打开括号就关闭它。
- 在你的代码中，确保你双检查并计算左右圆括号。
- 最后，如果你打开了圆括号，务必关闭它！

### 大写敏感
万一你不知道，函数和变量都是区分大小写的。在你工作时，非常容易犯这种静默错误。当你命名时，我们建议你保持一致。作为一个小技巧，只需记住 JavaScript 内部 CSS 属性将使用驼峰命名法（camelCase）。这是一个简单的示例：

```javascript
getElementById("theId") != getElementByID("theId");
```

- 你发现错误了吗？本应该是 `Id` 而不是 `ID`

```javascript
getElementById("theId") != getElementById("theID");
```

- 这一次呢？你抓到了！`Id` 不等于 `ID`。你可以看到这是一个常见的错误，尤其是当你试图快速操作时！

### 换行符和额外的逗号
当你编写代码时，你将避开硬换行。当你使用换行符时，它们会被解释为行尾的分号。这也发生在字符串中。当你在引号中包含硬换行时，你将得到错误。它最可能是“未结束的字符串”解析错误。这里有一个例子：

- 未结束的字符串错误：
```javascript
var bad= <ul id="myId">
<li>writing the text</li>
<li>even more text </li>
</ul>;
```

- 正确的换行
```javascript
var good= '<ul id="myId">' +
'<li> writing the text</li>' +
'<li> even more text </li>' +
'</ul>';
```

- 需要注意的是，这种分号规则在控制结构中并不适用。在控制结构中，闭合圆括号之后的换行符并不是由分号提供的。





- 为了修复这个错误，你将希望始终使用分号和括号。这样，你的代码会更易读，你不会被换行所困扰，而且当你移动代码时，永远不需要担心你的初始语句是否闭合。
- 如果你有多余的逗号，请记住最后一个属性不应该以逗号结尾。虽然某些浏览器（如 Firefox）不会被多余的逗号困扰，但 Internet explorer 则会。在编写代码时，请记住防患未缪于于医！

## 条件语句 (Conditional Statements)

在编写代码时，有三种常见的条件语句错误。以下是其中一些：

1. 在编写代码时，尽量不要因使用赋值运算符而产生困扰。当你这样做时，你实际上是在将第二个参数的值传递给第一个参数。显然，这会导致逻辑问题。当这种情况发生时，如果 `var2` 中的值不为零，它将返回 true 而不会抛出错误。

示例：

```javascript
if(var1 = var2) {}
```

* 这将返回 true 或 false，取决于 `var2` 的值。它将 `var2` 赋值给 `var1`。你必须小心，以防这并非你的本意！

2. 记住你所有的条件注释都必须在括号内。这似乎是一个简单的错误。然而，你会惊讶于发现它是多么常见！

示例：

```javascript
if(var1 == var2) {}
```

3. 对于大多数情况，JavaScript 是弱类型的。但在切换 `switch` 语句时，事实并非如此。当你使用 `case` 比较时，你的 JavaScript 将不是弱类型。

示例：

```javascript
var myVar = 1;

if(myVar == '1') {
alert ("hey");
}

switch(myVar) {
case '1' :
alert("hey");
```

* 在第一行中，你的代码将返回 true，因为 JavaScript 是弱类型的。
* 至于第三行中的 alert，它会显示，因为大多数时候，JavaScript 不关心数据类型。
* 在最后一行，你的 alert 将不会显示，因为你的数据类型不匹配。
* 但是，如果你想让 JavaScript 也检查数据类型，而不是使用两个等号，你应该使用三个等号 (===)。在这种情况下，将不会触发 alert：

```javascript
var myVar = 1;

if(myVar === '1') {
alert ("hey");
}
```

## 变量作用域 (Variable Scope)

并不意外，有很多问题可能源于变量作用域。其中一些问题包括在函数内部从局部变量覆盖全局变量，甚至错误地认为局部变量是全局变量。正如你稍后将学到的，最好根本不要使用任何全局变量。如果你无法避免它们，至少要知道如何避免它们。

当你有全局变量时，记住它们不会通过典型的 `var` 关键字声明。相反，你必须使用特定的术语来声明变量，以防止它们具有全局作用域。这里有一个变量在声明函数后并获得全局作用域的示例：

CODE:

```javascript
anonymousFunction1 = function(){
globalvar= 'global scope';
return globalvar;
} ();

alert(globalvar);
```

* 在这段代码中，缺少了 "var"，当这种情况发生时，它会在全局声明。

CODE:

```javascript
anonymousFunction2 = function(){
var localvar = 'local scope' ;
return localvar;
} ();

alert(localvar);
```

* 在这段代码中，有一个局部声明的 "var"。
* 最后，将出现 "localvar is not defined." 的错误。如你所示，这是因为没有全局定义的 localvar。

## HTML id 冲突 (HTML id Conflicts)

这个小错误更多是关于 CSS 的最佳实践，但有时当你遇到 JavaScript 问题时，它可能会有所帮助。HTML id 允许 JavaScript 进行 DOM 绑定以实现索引。正如你记得的，属性和函数在你的代码中共享同一个命名空间。所以，如果你的属性和函数恰好同名，你可能会创建一个逻辑错误。这些错误很难追踪！当你使用 JavaScript 编写代码时，我们建议避免使用与 ID 值相同的变量名。此外，如果你在标记 HTML，请尽量不要使用属性名作为值。这有助于避免混淆。

这是一个示例：

CODE:

```javascript
var listitems= document.getElementsByTagName('a');
var aCount= listitems.length;
```

* 如果你恰好有一个 `<a id="length">`，它有时返回 `<a>` 而不是你请求的计数。这就是为什么记住这个小贴士非常重要。

## 字符串替换 (String Replace)

这种字符串替换在代码世界中是另一个非常常见的错误。你可能犯了假设你的字符串 `replace` 方法行为的错误。当你做出假设时，可能会影响你所有可能的匹配项。如果你之前没有意识到，JavaScript 只会更改字符串中 `replace` 方法的第一个出现处。如果你想替换所有出现处，需要你先设置一个全局修饰符（modifier）。

这是一个很好的例子：

CODE:

```javascript
var myString = "the string were talking about";
myString= myString.replace(/ /, "%10"); //
"the%10string were talking about"

myString = myString.replace(/ /g,"%10"); //
"the%10string%10were%10talking%10about"
```

‘this’

如果你习惯使用 JavaScript 编写代码，你可能犯了忘记使用 `this` 的错误。如果这让你感到陌生，JavaScript 中的函数是作为对象属性访问的。当你未能使用 `this` 标识符时，可能会丢失。

## 函数覆盖/重载 (Overwriting/ Overloading Functions)

在编写代码时，如果你多次声明同一个函数，对该函数的最后声明将覆盖之前的任何函数。这可能很难，因为它不会给你任何警告或错误提示。在 JavaScript 中没有重载。这就是为什么在代码中避免任何 JavaScript 核心名称很重要。你还应该希望避免过度包含 JavaScript 文件。如果发生这种情况，它可能会覆盖另一个脚本中的相同函数。相反，我们建议使用命名空间和函数，这里有一个示例：

CODE:

```javascript
// 创建命名空间
// 如果命名空间不存在，则创建它。
if (!window.THENAMESPACE) {
window [ 'THENAMESPACE' ] = {}; }

// 注意此函数在匿名函数内部可见
function myFunction (var1, var2){
//局部函数代码将在这里 }

/* 这将局部函数附加到你的命名空间中。这意味着它在外部使用命名空间时是可以访问的*/
window['THENAMESPACE']['myFunction'] = myFunction;

};

// 注意括号将开启一个立即执行 //
```

* 是括号包含了使你的匿名函数生效的代码。

 正确使用 ‘For Each’ (Using ‘For Each’ Correctly)





正如你所记得，JavaScript 使用 `"for"` 循环来处理你的对象属性、属性和方法。它使用代码来遍历对象中的所有属性名。此循环也会包含你并不希望出现在代码中的某些函数和属性。如果你想过滤掉这些值，你可能需要使用 `hasOwnProperty` 或 `typeof` 函数。在编码时，我们建议避免使用 `each`；你唯一想要使用 `each` 的时机是你想要遍历方法和对象属性时。

以下是编码时的几点提示：

- `for (var myVar in myObject)` 上述代码用于遍历特定对象属性中的特定变量。这与属性的顺序无关。`for…in` 循环不会迭代内置内置属性。
- `for (var i=0; i <myArray.length; i++)` 这段代码应用于你数组的所有元素。它将遍历上述所有元素。
- `for each (var myVar in myObject)` 这段代码用于你对象所有属性中的特定变量。
- 如果你想解决这个问题，在用于对象时，你将需要使用 `for…in`。当你想要循环数组时，只需使用 `for` 即可。这是一个示例：

```javascript
listItems=document.getElementsByTagName('La');

for each (var listitem in listItems){

}
```
- 注意：上述代码将遍历对象的所有方法和所有属性。
- 这包括任何原生属性和方法。请注意，它不会遍历数组。相反，它会抛出错误。
- 由于存在一个你想要查看的对象数组，请如下使用 `for` 循环：
```javascript
for ( var i = 1; i <listItems.length; i++) {

}
```

## 未定义与空 (Undefined and Null)

回到基础编码 101，理解这些术语并不是同一个非常重要！万你忘记了，`null` 用于你代码中的对象。`Undefined` 将用于你代码中的变量、方法和属性。为了成为 `null`，所讨论的对象需要被定义。如果未定义，你可以测试它是否为 `null`。当对象未定义时，它无法被测试并会抛出错误。这是一个示例：

```javascript
if (myObject ! == null && typeof(myObject) ! =='undefined') {
}
```
- 注意：如果 `myObject` 恰好是 `undefined`，记住它不能被测试为 `null`。相反，它会抛出错误。

```javascript
if (typeof (myObject) ! == 'undefined' && myObject !== null) {
}
```
- 注意：这段代码负责处理 `myObject`。

### 1. 不要在本地持久化密码 (DO NOT persist password locally)
正如你想象的，如果你在代码中存储任何密码，可能会创建安全漏洞。这些是你希望尽力避免的方面。你最不想的就是因为犯了简单的错误而被攻击者利用。任何情况下，我们建议不要在 `sessionStorage`、`Cookies` 甚至 `localStorage` 中持久化密码。相反，允许用户通过正常机制获取密码。只需避免将其放入代码中。

### 2. 不要在客户端处理代码中使用硬编码的用户名（或密码）（DO NOT use hard code usernames (or passwords) in your client processed codes)
再次，这是一种创建安全漏洞的简单方法。对于某些编码员来说，这可能会让你成为一个懒惰的程序员！即使你的代码只是测试或简单的演示，也不要在代码中使用你的用户名和密码。你永远不知道谁会拿到代码。互联网是一个非常广的世界。

### 3. 不要在程序模板或代码中使用硬编码字符串（DO NOT use hard code strings in a program template or code）
当你编码时，你应该始终假设你的代码将被翻译。如果你想避免偷懒，至少为你的字符串的键值创建一个映射。

这是一个简单的示例：

```javascript
this.Text = {
    "greeting" : "Hello",
    "firstName" ; "First name",
};
```




-   在编写代码时，务必注意你的模式。有些人犯了这样一个错误，即通过检查事件的 `target.label` 来判断它是否为源按钮。相反，我们建议使用 `"class"` 或 `"id"` 标识符。这样，即使应用程序被翻译，它也不会崩溃。

### 5. 命名变量时切勿使用连字符（hyphens）

编码可能是困难的；这就是为什么我们建议不要在变量名中使用连字符。如果发生这种情况，它可能会被误认为是减法操作。例如：

```javascript
var hello-name = "Welcome";
```

-   按照这段代码的设置方式，它将尝试从世界中减去 name。显然，这将抛出一个错误。

### 6. 不要在此代码中遗留 "debugger" 语句

提醒一下，`"debugger"` 语句用于在任何测试期间强制浏览器在断点处停止。这是帮助大多数开发者快速、高效地定位错误的代码。然而，如果意外遗留在代码中，可能会导致其他故障。相反，我们建议使用浏览器工具手动设置断点。这在最终可以为你节省时间并避免麻烦。

### 7. 不要使用函数 "eval()"

有一个开发者常用的俗语叫做 "eval is evil"（eval 是邪恶的）。这应该是一个容易记住的观点：你应该很少使用 `eval`，如果非要用的话。这段代码是让你的代码产生很多坏结果的一种非常简单的方法。除非你清楚自己在代码中做什么，否则必须始终对来源保持信任。如果不是，它可能会导致你的代码出现漏洞。正如你之前学到的，这是你不惜一切也要避免的事情！

### 8. 永远不要使用全局变量

这是我们将反复强调的一点。当你定义局部变量时，请务必使用 `var` 语句。否则，变量将被放置在全局作用域中。你需要避免这一点。相反，我们建议使用基于 AMD 的加载器。这样，它将消除任何全局命名空间的包或模块。请注意，这不适用于提供全局对象的环境（如 `console`、`navigator`、`window` 或 `document`）的浏览器。

### 9. 不要留下任何悬空逗号（dangling commas），特别是在对象定义和列表中

虽然在现代技术下，大多数浏览器实际上允许这样做，但在过去这曾会导致 Internet Explorer 抛出错误。应该指出，留下悬空逗号可能会导致一些粗糙的编程。大多数情况下，这类问题出现在 `define` 语句中。在声明的类的最后一个方法/函数之后也发现过这种情况。这是一个错误的示例：

```javascript
var a = [1,2,3,];
var b = { a:1, b: "B", c: x,};
```

-   作为一个通用提示，你可能希望通过 `Array` 来生成你的视觉列表。这样，你可以合并结果。这里有一个示例：

```javascript
console.log ( "A List of Names: ", nameList.join ("firstname, lastname") );
```

### 10. 务必在函数顶部定义所有的局部 var

虽然这并非必须，但通过在函数顶部定义局部变量，可以使代码更加简洁。局部变量通常位于 `"function"` 作用范围内。换句话说，它们在任何嵌套函数内部都是可的。这并不意味着它们只存在于闭块内。相反，在整个函数中随机放置的 `"var"` 定义可能会导致意外的变量重新赋值等错误。请记住，这也适用于 `for (var I in...)` 块。虽然变量 `I` 不会在块级作用域，但它会在外部包含的函数作用域内。这可能会变得非常困惑，因为这是其他编程语言中的常见做法。请注意，JavaScript 的情况并非如此。请将你的局部变量定义在函数顶部，以避免任何意外的副作用。

### 11. 务必使用 (======) 显式比较符

在 JavaScript 中，你总是希望使用显式比较符而不是任何强制转换的比较符。通过使用强制转换的比较符，你将能够转换任何类型，然后对它们进行匹配和比较。

这里有一个这样做的极佳示例：

```javascript
"Hey" == 2
" " == 1
1 == true
```

-   与 `!==` 相比，使用三等号将强制你的代码对值进行纯粹比较。

### 12. 务必使用快捷方式进行值的默认值赋值

在编写代码时，你的主要目标是让代码快速且易读。通过在操作赋值中使用逻辑或（OR），可以让你的代码拥有默认值。这里有一个对输入参数进行简单验证的示例。这样做可以确保代码在任何预期的对象上运行。

```javascript
//"Args" 如果未定义则将默认为空对象
args = args || {} ;
//如你所知，args 是一个对象。现在它被定义了，这样执行 var greeting 才是安全的：
var greeting = args. Greeting || "Hello";
```

### 13. 务必将大括号放在块定义的右侧

虽然这是一种个人风格选择，但始终建议将大括号放在块定义的右侧，以保持代码安全。随着你开始编写更多代码，你会发现一种让你的工作更轻松的风格。这里有几个放置括号的示例：


-   **正确：**
```javascript

```

### 14. 务必在行末尾使用分号

虽然在行末尾使用分号在技术上不是强制的，但你的代码这样写会更好。与其猜测编译器将如何解释这些行，不如直接在末尾放置分号，这样就没有猜测游戏了！

### 15. 务必遵循函数和变量的命名规范

这样做有助于创建更整洁的代码。记住，你并不总是那个阅读/编写自己代码的人。为了保持代码的一致性，请使用以下命名规范来保持有序：

    示例：`var A= 1.2`

    示例：`_myUsername`

    示例：`camelCase`

### 16. 务必为你的 NLS 字符串使用双引号

在编码中，许多语言会大量使用单引号作为特定语言的一部分。大多数情况下，翻译人员无法理解 `"JSON"` 结构样式。如果发生这种情况，单引号字符串会导致无效字符串。

# 第三章：注释和日志的最佳实践

在使用 JavaScript 编写代码时，你有一些技巧可以让你的注释和日志变得更简单。记住，当你工作或练习编码时，你希望尽所能地保持代码的整洁有序。日志和注释都应该贯穿整个代码。请注意，使用任何一种都不会产生性能开销。大多数情况下，它们在你的构建阶段就会被移除。

在这里，我们将为你提供一个在处理日志和注释时需要记住的快速列表：

-   务必使用正确的日志级别
-   所有复杂逻辑都使用注释
-   使用标准日志记录任何有用细节
-   任何公共函数、变量或模块都使用 JSDoc 语法
-   不要字符串拼接

### 1. 务必使用正确的日志级别





请注意，`WL.logger` 和 `Console` 都支持几种不同的日志级别。如果你不记得了，它们包括：`warn`、`error`、`log` 和 `debug`。当你在编码中针对特定情况使用适当级别时，将帮助你更好地管理记录的日志。例如，如果你正在构建代码，对于 Dojo 的默认设置将移除出现在“error”以下的日志。在这种情况下，任何 `console.error()` 都会保留在代码中。这样做的问题是，在你完成构建后，任何错误情况都将从代码中移除并导致其丢失。

### 2. 务必对所有复杂逻辑使用注释

大多数情况下，如果你具备技能，JavaScript 代码是可读的。但也有某些时候，代码变得过于复杂，甚至无法解决复杂问题。例如，为了让其他人（如新手）理解代码而进行重构代码并不总是实际的。这对于那些试图让代码“优雅”的开发者来说也是如此。为了保持简单并让大家的生活更轻松，请为你的复杂代码编写注释。归结底，这将有助于所有人理解代码。

### 3. 务必对任何有用细节使用标准日志

当你编写代码时，你的日志应该包含有意义的内容。大多数开发者会希望通过使用 `console.log()` 在记录日志时保持慷慨。在创建日志时，务必提供价值内容，如模块、`source` 和 `function`。你包含的任何消息都应该是描述性的并包含有用的变量。我们还建议避免使用 `alert()` 语句代替日志。在大多数情况下，它可能会遗留在代码中，并让大家的工作变得更加困难。

### 4. 务必对任何公共函数、变量或模块使用 JSDoc 语法

如果你还不知道，`JSDOC` 是你用来注释 JavaScript 代码的一种方法。这就是为什么正确地注释你的公共变量和函数至关重要的原因。从本质上说，私有变量和函数可以记录，但它们重要性较低。如果你正在使用可复代码，它可能会被贡献到公共或私有库中，此时它需要适当的文档说明。

### 5. 勿使用字符串拼接

在你编写代码时，我们建议在记录日志时使用多个参数。这样，你就可以避免使用字符串拼接。这是日志记录中常见的一种反模式。

这里有一个错误的示例：

```
Console.error ("Invalid arguments provided: " + args);
```

- 在这种情况下，代码将失败。输出必须对对象运行 `toString()`。在这种情况下，它将显示如下：
`Invalid arguments provided: [Object]`

- 取反，你将希望使用多个参数来显示你想要的对象。这里是正确的示例：

```
Console.error ("Invalid arguments provided:", args);
```

- 如你所见，这是一个简单的修复，但你可以相当容易地完成它。

# 第 4 章：提高性能的技巧

无论你是编程界的新还是已经实践了一段时间，你都可以向自己承认你会犯错。记住，这没关系。总有方法帮助你在编码中表现更好。

在本章中，我们将为你提供几种帮助改进代码的方法。从最小化 DOM 访问到对循环内部的任何逻辑保持怀疑，总有改进的空间。

如果你赶时间，这是你的清单！

- 务必确保你的第三方库始终经过优化
- 最小化任何 DOM 操作和 DOM 访问
- 将你的 DOM 保持最小
- 对循环内部的逻辑保持怀疑
- 延迟 JavaScript 加载
- 减少循环中的活动量

### 1. 务必确保你的第三方库始终经过优化

在编码时，你要意识到你**始终**需要优化任何自定义的 JavaScript。此外，你必须确保你也在使用任何第三方库的优化版本。作为一个通用的提示，最小化的库在其标题中会包含 `".min"`。在研究时，你将想要寻找承诺你提供的是优化版本而非开发者源码的网站。

### 2. 务必最小化任何 DOM 操作和 DOM 访问

如果你还不知道，`DOM` 与你应用程序中的任何其他代码相比都缓慢得多。这就是为什么在可能的情况下最小化对 `DOM` 的访问至关重要的原因。如果你绝对需要访问某个节点，我们建议只这样做一次，将结果存储在本地变量中。最后，我们建议构建一个大的 `DOM` 片片并一次插入。与将节点构建到你的 `DOM` 中并在每次迭代它相比，这是一个好得多的选项。

### 3. 务必将你的 DOM 保持最小

如果你在为应用程序编写代码，你将希望代码尽可能快速且无缝。遗憾的是，随着复杂性和 `DOM` 大小的增加，性能将会下降。通过主动控制 `DOM` 大小，你可以改进操作的重流。幸运的是，你有两个基本选项来帮助最小化你的 `DOM`。首先，你可以销毁视图以保存状态。你还需要销毁子元素。虽然管理状态和子组件可能会变得复杂，但你的用户实际上不太再次访问此视图。相反，你将希望清理任何 `DOM` 资源或内存。

你的第二个选项是使用 `DomCache` 代码。为此，代码将卸载视图的节点树。作为回报，它将转化为 `DomFragment` 变量并重新插入 `DOM`。如果你需要视图，这是最佳选择。

### 4. 对循环内部的逻辑保持怀疑

对于大多数开发者来说，使用循环遍历你的元素和数据是正常的。然而，你不希望在循环中进行这些操作。记住，这可能会导致许多负面性能。越早在循环之外捕捉 DOM 访问、存储访问、数学计算、AJAC 调用或其他操作就越好！

### 5. 延迟 JavaScript 加载

如果你将脚本放在页面底部，它将允许浏览器先加载页面。但是，当你的脚本加载时，浏览器将无法启动其他下载。如果发生这种情况，其他渲染活动可能会被阻塞。相反，尝试在你的脚本标签中使用 `defer="true"` 代码。此属性将在页面解析完成后执行。请注意，这适用于外部脚本。尝试以下代码示例：

```
<script>
window. onload = downScripts;

function downScripts ( ) {
  var element = document. createElement ("thescript");
  element.src = "theScript.js";
  document.body.appendChild(element);
}
</script>
```

### 6. 减少循环中的活动量

记住代码中的循环将包含一个语句。该语句将在循环的每次迭代中执行。如果你将语句放在循环之外，这将帮助你更快地运行循环。

这是一个有助于提高性能的错误代码和代码示例：

- **错误代码：**
```javascript
var I;
for (I = 1; I<arr.length; I++) {
```

- **更好的代码性能：**
```javascript
var I;
var m = arr.length;
for ( I = 1; I < m; I++) {
```

Charlie 需要一种可以轻松学习的方法。他很快发现了一系列让他学得更快更好的教学系列。通过同样的方法，Charlie 成功地学习了不同的编程语言，现在通过写作教授这些主题。

通过他编写的计算机编程书籍，他希望为对计算机主题感兴趣的读者提供巨大的价值。
