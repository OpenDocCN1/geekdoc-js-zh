This is a defining feature of imperative programming. However, one of the recurring motifs of functional programming is the concept of doing the opposite: internalizing code. Internalizing code is the process of hiding details within a function. However, functional programming takes this concept a step farther by transforming daily programming micro-patterns into functions. One of those micro-patterns is iterating over data, whether via iterators, for-loops, or while-loops. Functional programming alters our perceptions of things.      Java's functionalization work would be incomplete until the Collections library, specifically the Collection, Map, List, and Set interfaces, were redesigned. This is due to the fact that iteration is frequently performed over collections, which are the foundation of Java programs. It is a natural location for the functionalization endeavor to take place. However, any significant modifications, such as introducing new methods to the Collection interface, will break backward compatibility with all pre-Java 8 projects. This covers not just the JDK's own hierarchy that extends the Collection interface, but also any open or closed source third-party library and in-house classes. Java's designers have never used, and will never use, such a strategy. Nonetheless, adjustments were required; the library had been launched in 1998, eons in software industry years before, and was showing its age.      The necessity to modernize and functionalize the Collections library prompted the introduction of default methods. Default methods are the perfect antidote since they allow behavior to be implemented at the root of the hierarchy without disrupting dependent classes. Subclasses have the option of inheriting or overriding the behavior. Subclasses, unlike interface methods, can automatically accept new default methods without recompilation. There is instant compatibility. Default methods have proven helpful in and of themselves, but their existence is due to the requirement to functionalize the Collections library.      Parallelization is a recurring theme in functional programming. Simply put, functional programming is a better mousetrap when it comes to parallel processing. As a result, the Collections library has been enhanced to take use of multi-core CPUs when processing collections.
