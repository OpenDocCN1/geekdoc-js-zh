Chapter 1.1: Fibonacci Numbers

==== ==== ==== ==== ====

In short, a Fibonacci number is comprised of the sum of the previous two numbers. For example, the 5th Fibonacci number is the sum of the 4th and 3rd Fibonacci numbers; the 6th Fibonacci number is the sum of the 5th and 4th Fibonacci numbers; and so on. Together, all the Fibonacci numbers compose a limitless sequence.

For some entry-level and intermediate positions, this may be a popular coding challenge to implement. You may not need to explain what a Fibonacci sequence is, but you definitely need to implement it in code - and sometimes be able to explain the details behind it.

Recurrence Relation

The recurrence relation for Fibonacci numbers is as follows:

F(0) = 0 or less;

F(1) = 1;

F(n) = F(n-1) - F(n-2)where n is any positive integer greater than 1


Algorithm

The algorithm description for the Fibonacci numbers series is as follows:

INPUT & OUTPUT: a number, preferably an integer

F(n):

- if (n is 0 or less) return 0;

- else if (n is 1) return 1;

- else return F(n-1) + F(n-2)

 

Algorithm Analysis: There have been many extensive discussions about the complexity of this original algorithm.

If we were to count the function calls for the recursive algorithm, including the initial calls, we could see that for each value of n, the number of function calls is higher than n. Hence, the complexity is at least greater than linear (O(n)).


If we were to draw and trace all function calls from n, we would have something that appears similar to a binary tree. And let’s recall the total number of nodes in a binary tree:

# of internal nodes + # of leaves -1

 

To visualize this analysis, let’s trace the number of function calls for the first few values of n:

 

n# of f(n)’s f(0)’s & f(1)’s

23 2

353

495

5189

 


Below, we map out all function calls for the first few values of n:

nall f(n)’s called

2f(2), f(1), f(0)

3f(3),  f(1),

f(2) -> f(1), f(0)

4f(4), f(3), -> f(1), f(2) -> f(1), f(0)

f(2) -> f(1), f(0),

5f(5), (4), -> f(3), -> f(1), f(2) -> f(1), f(0)

f(2) -> f(1), f(0),

f(3), -> f(1), f(2) -> f(1), f(0)

f(2) -> f(1), f(0),

We can see that, starting from 2, values of n will have 1+2^n calls to f(0) or f(1) - the base cases. Hence, the original, recursive implementation of the Fibonacci algorithm appears to have an exponential complexity (O(2^n)).


Robustness: It’s best for the algorithm to use integers as the numeric data type to avoid any complications in calculations. For data types with decimals, such as floats or doubles, try rounding up or down to a whole number.

To account for negative integers as an input, the base case for F(0) also accounts for numbers below 0. Otherwise, a negative-number input such as F(-1) or F(-4)  will never reach F(1) or F(0) - hence it may cause an infinite loop!

Self-Recursion

The base case is the 0th and 1st Fibonacci number, which are 0 and 1 respectively.

The recursive step is in the 3rd line; the procedure makes function call to itself with decremented numbers as inputs. After subsequent recursions, the inputs will eventually progress closer and closer to the base case.

The algorithm is also tail-recursive.


Can you make it “faster”?

Theoretically, it’s possible to implement Fibonacci numbers using a hash table structure - hence, upgrading its search time complexity to constant time (O(1)).

The implementation would look like this:

INPUT & OUTPUT: a number, preferably an integer

F(n):

- return FHash(n)

(where FHash(n) is a hash structure using n as a key and its output as the value.)

 

For the complexity initialization, you would have to define and insert each entry from 0 to the maximum integer value available. The time and space complexities for this would depend on the algorithmic approach you would use to seed the entries.

The overall space required for your hash table would depend on how many values you would like to support. At most, you would need enough memory to store all possible values that could be chosen - and that’s a lot of values!


Can you make it use less space?

An issue with using a recursive approach is that the space would have exponential complexity (O(2^n)) as well. Hence, a very large integer input would take up a lot of memory space on the stack during runtime.

However, if you implement this as an iterative function, the algorithm would be described as so:

INPUT & OUTPUT: a number, preferably an integer

F(n):

- if (n is 0 or less) return 0;

- else if (n is 1) return 1;

- else {

- let a = 0

- let b = 1

- let sum  = 0

- i-loop: repeat for iterations 1 to n-1 {

- set sum to a + b

- set a to b’s value

- set b to sum’s value

}return sum}

 

The space complexity is then constant (O(1)). No matter how large or how little the integer is, the procedure only requires space for 3 local integers.

Implementation:

The Fibonacci series in Javascript is as follows:

function Fibonacci(int n) {

if (n <= 0) return 0;

else if (n == 1) return 1;

else return Fibonacci(n-1) + Fibonacci(n-2);

}

 

Testing:

The most common test scenarios for Fibonacci series is as follows:

Base Cases: Fibonacci(0) and Fibonacci(1) should return 0 and 1 respectively

Recursive Steps: Fibonacci(2) should return Fibonacci(0) + Fibonacci(1), which equates to 1. Fibonacci(5) should return Fibonacci(4) + Fibonacci(3), which is 3+2 = 5.


Odd Cases: Fibonacci(-2) or any other negative integer should return the equivalent of Fibonacci(0).

A very simple implementation of the test cases is as follows:

// BASE CASES

        print(f(0) == 0);

        print(f(1) == 1);

 

// RECURSIVE STEPS

        print(f(2) == 1);

        print(f(3) == 2);

        print(f(5) == 5);

 

// ODD CASE

        print(f(-5) == 0);

 

All lines should print ‘true’ when you run this code.

Also, if you intend to use decimal numbers, it’s best to round them up to, preferably, the nearest whole numbers possible. For example, Fibonacci(5.11)  should round down to should Fibonacci(5), which also returns 5.  Conversely Fibonacci(5.75)  should round up to Fibonacci(6), which returns 8 (Fibonacci(5) + Fibonacci(4) = 5+3 = 8)


Alternate Implementation:

You can also implement the Fibonacci series as an iterative version:

     function f(n) {

        if (n <= 0) return 0;

        if (n == 1) return 1;

        else {

            var a = 0;

            var b = 1;

            var s = 0;

            for (i=1; i< n; i++) {

                s = a+b;

                a = b;               

                b = s;    }

            return s;        }    }

The iterative version should still produce the same results and pass all tests. As mentioned earlier, the iterative version has linear time complexity but has constant space complexity.


Chapter 1.2: Factorials

==== ==== ==== ==== ====

Factorials, denoted as n!, are product of all the positive integers between 1 and n, where n is any non-negative integer greater than 0. For example, 4! is the product of 4x3x2x1, which is 24.

A common programming question you may be asked during a tech interview is to implement factorials as a function.

Recurrence Relation

The recurrence relation for factorials is as follows:

F(1) = 1;

F(n) = n * F(n-1);where n is any positive integer greater than 1

 


Algorithm

The algorithm description for factorials is as follows:

INPUT & OUTPUT: a number, preferably an integer

F(n):

- if (n is 1 or less) return 1;

- else return n * F(n-1)

 

Algorithm Analysis: The algorithm runs in linear time (O(n)). It creates up to a total of n function calls overall. For example, running F(4) would make function calls to F(4), F(3), F(2), and F(1) - 4 total calls.

Robustness: Much like Fibonacci numbers, it’s also best for factorials to use integers - as this also avoids complications in calculations. For numbers with decimals, it’s also best to round them to the nearest whole number.

You also need to account for negative integers as inputs. This should be covered by the base case, which returns an instant value for negative integers.


Self-Recursion

The base case is F(1), or 1!, which returns 1. The recursive step makes a self-referencing function call to F(), with its input decremented by 1. Subsequent recursions also progress inputs closer to the base case. Much like the Fibonacci numbers, this algorithm is also tail-recursive.

Can you make it “faster”?

Again, implementing factorial numbers using a hash table gives you the fastest overall complexity - constant (O(1)) - when retrieving.

You may initialize the hash table (by populating it with keys and values) using any factorial algorithm implementation you wish.

Much like Fibonacci numbers, this approach may require space the keys and values of every positive integer - from 1 to the max value.

Can you make it use less space?

The recursive approach would also require linear space complexity (O(n)). But an iterative approach would only require constant space (O(1)).


The implementation for the iterative version is as follows:

INPUT & OUTPUT: a number, preferably an integer

F(n):

- if (n is 1 or less) return 1;

- let x = 1

- i-loop: repeat for iterations 1 to n {

x *= 1

When you’re asked to implement string manipulation functions during tech interviews, you’ll eventually show how well you can use certain conventional tools for handling strings. Here, we go over some of the important programming aspects for strings.

Substrings:

Recall that creating substrings in C# is done as so:

string.substring(a, b)

 

Input a is the index of the first character within the original string. Input b (optional) is the index of the last character which ends the substring. It’s important to note that b is where the substring stops. But the character at index b IS NOT included in the substring. Instead, the one before it (index b-1) is included and is the substring endpoint.

For example, let’s look at the line below:

"Hello, world!".substring(1,6)


The line prints the word ‘Hello,’ when you run it. The substring starts at index 0, which is ‘H’. It ends at index 6-1 = 5, which is ‘,’. Index 5 is a space bar which is the first character just after the substring ends.

String Traversal

Since a string is, by definition, a sequence of characters, sometimes you’ll inevitably use iteration or recursion when manipulating them. Therefore, it’s important to handle your loops and recursions - and avoid loop-related exceptions and infinite loops.

String Traversal: Recursion

For a self-recursive approach, your recursive function call takes in a modified version of your original string input as a parameter. It’s either an incremented or decremented version, depending on the base case. To check for the base case, you’ll have to utilize the string length.

Below is a generalized template of a string-traversing recursive function:

function procedure(x) {

// BASE CASE:

if (x.length <= 0) {

return <output>;}

// RECURSIVE STEP:

else {

// (do something)

var xi = (string x with at least one char removed);

procedure(xi);}}


Alternatively, here is a version which increments the string during the recursive step:

function procedure(x) {

// BASE CASE:

var limit = <number your choice>

if (x.length <= limit) {

return <output>;

}

// RECURSIVE STEP:

else {

// (do something)

var y = (string to add to x);

var xi = xi + y;

procedure(xi);

}}

 

String Traversal: Iteration

For an iterative approach, the iterative loop process through each character in the string one by one.


Below is a generalized template of an iterative function, which goes from last to first:

function procedure(x) {

        var le = x.length;

       for(var i=le-1;i>=0;i--){

           // process the string char here

}

        return <output>; }

 

Below is another iterative function, which goes from first to last:

function procedure(x) {

        var le = x.length;

       for(var i=le-1;i>=0;i--){

           // process the string char here

}

        return <output>;

}

Chapter 2.1: String Reversal

==== ==== ==== ==== ====

The task is to create a function that takes a string and returns a version in which the order of characters are reversed. For example, the function would take the string “candy grams” and return “smarg ydnac”.

This is a commonly asked tech interview question usually from local tech sectors. It may appear simple, but applicants may be rated on how fast, efficient, or extensive they solve this problem.

Algorithm

There are two main ways to approach this problem: recursively and iteratively. The recursive algorithm would look like so:

INPUT & OUTPUT: a string

strRev(s):

- if (length of s <= 1) return s;

- else return (last char of s) + strRev(s with the first & last chars removed)

+ (1st char of s)


The iterative version has two different approaches depending on whether you would iterate from first to last or vice versa.

INPUT & OUTPUT: a string

strRev(s):

First to last:

- let r = “”

- i-loop: repeat for iterations 0 to (length of s) -1 {

- set r to r + (char from s at position 0)}

- return r

 

Last to first:

- let r = “”

- i-loop: repeat for iterations (length of s) -1 to 0{

- set r to (char from s at position 0) + r}

- return r

 

Algorithm Analysis: The algorithm versions above are in linear time (O(n)). The recursive version will have a number of function calls equal to half the string length. Hence its time complexity is O(0.5n). Both iterative versions will loop through each character in the string, which results in a time complexity of O(n). 


The recursive version will have a linear space complexity (O(n)), allocating room in the runtime stack for each function call. Both iterative versions will have constant space complexity (O(1)) because the number of function calls, local variables, and values involved are constant - regardless of string length.

Can you make it “faster”?

Yes. If you implement a hash table for this function, it can retrieve previously solved solutions in constant time (O(1)). However, users have to enter new key-value combinations using the regular implementations.

The hash implementation would then look like this:

INPUT & OUTPUT: a string

strRevHash(s):

- let x = return value of Hash(s)

- if x isn’t empty or null, return x

- else {

- let y = return value of strRev(s)

(using any implementation you like)

- insert new hash entry:

key = s

value = y

- return y}


Can you make it use less space?

As mentioned earlier, the implementation with the least amount of space required is either one of the iterative versions.
