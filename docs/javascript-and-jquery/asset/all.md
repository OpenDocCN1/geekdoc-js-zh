Variables are the way we store values ​​that we want to use at a later time. Variables can be of several types of text, numbers, or other data such as arrays and objects, or even code scripts (in a significant way stored in a variable). The variable is declared with the var statement:

## Functions

Functions are a key component of JavaScript software because it provides a way to create small functions in the program in an independent and structured part. For example, suppose a function that combines two numbers:

function (a, b) {

    return a + b;

}

This function takes two factors, a and b, then add them together and then return the sum as a result of the function.

The previous example is properly formulated JavaScript, but it does nothing at all, because there is no way for us to ask this function to add any two numbers after. So we have to find a way to call the function, and we can do that by assigning it to a variable first:

var addTwoNumbers = function (a, b) {

  return a + b;

}

What we did in the last example is that we took an function expression and assigned it to a variable. We can now call this function using the variable name:

log (addTwoNumbers (1, 1)); // Print 2

Alternatively, we can use a function declaration to give our function a name:

function addTwoNumbers (a, b) {

  return a + b;

}

Both methods allow us to call our function in the same manner, but care must be taken when adopting the last method for reasons explained by this post.

Conclusion: Naming functions by declaring a function may lead to unexpected results if you do not fully understand a feature of JavaScript known as hoisting. Detail of this feature is out of the scope of this series, but we will rely on assigning functions to variables at this time.

## Logic and validation

JavaScript provides the words if and else, as well as the triple parameter, to allow some commands to be executed only when certain conditions are met. JavaScript determines whether a condition is met by checking the "correctness" of a value or phrase. Because JavaScript is a dynamically typed language, we can use any value or any combination of values, but the rules for verifying whether a specific value or phrase is true or false may cause some confusion.

Below is an example of a simple conditional (if) clause in JavaScript. The sentence checks the validity of the number 1, and because 1 is a "truthy" value, the script in brackets {} will be executed after the if statement.

if (1) {

  // This will be executed

  log ('1 is truthy');

}

The truth is that most of the values ​​in JavaScript are "true", and only five values ​​in the language are considered "false" (falsy):

    undefined (the initial value of each variable is imposed without assigning a value to it)

    null

    NaN (not a number)

    0 (number zero)

    (Empty text string)

When we want to check a value for an "error", we use the parameter::

var a = '';

if (! a) {

  // This command will not be executed if it is a correct one

  log ('a was falsy');

}

As for the value of NaN, it has a special situation. When it is checked in a simple conditional statement, it is false:

var notANumber = 'four' - 'five';

if (! notANumber) {

  // This will be done

  log ('! notANumber was truthy');

}

When we compare the value of NaN to false, we get a "wrong" value:

var notANumber = 'four' - 'five';

if (notANumber == false) {

  // This command will not be executed

  log ('notANumber was falsy');

} else {

  // This will be executed

  log ('notANumber was truthy');

}

It is important to remember that all other values ​​except for the previous five are considered true, including empty matrices, blank objects and all non-empty text strings (including the text string '0') and all numbers except 0.

## Logical Operators

Logical operators allow an evaluation of both sides of the logical operation by executing the AND (&&) and OR (||) operations.

var foo = 1;

var bar = 0;

var baz = 2;

foo || bar; // returns 1, which is the correct value

bar || foo; // returns 1, which is the correct value

foo && bar; // returns 0 which is the wrong value

foo && baz; // returns 2, which is the right value

In the case of the parameter ||, the returned value is the first value to validate the sentence, or the last value. In the case of the && parameter, the returned value is the first value that proves the sentence error, or the last value.

You might see Boolean operators being used smartly to control the flow of the program:

foo && bar (); // Call the bar function only when foo is correct

var bar = baz || createBar (); // Use baz as the value for bar, unless it is

                               // false, and then create a bar

This method is nice and brief, but it may make reading the program more difficult, especially for beginners. You have to learn it to know it in other people's programs, but I advise you to stay away from using it at first, and use the traditional if and else because they are clearer.

## Operations on numbers and strings

Dealing with numbers in JavaScript may sometimes give unexpected results, due to the way numbers are represented internally in JavaScript, for example: When adding two decimal numbers, the result is a number very close to the expected value, but it is not completely equal:

log (0.0001 + 0.0002); // 0.00030000000000000003

You won't encounter this much when working with jQuery, but it's an important issue that you should pay attention to especially when dealing with decimal numbers like currencies. When performing calculations that require complete accuracy, you must convert the values ​​to integers before working with them, then convert them back to decimal numbers after completion.

JavaScript tolerates different types. When performing calculations using non-numerical values, JavaScript will not inform you of an error. Rather, it will continue the process with results you may not expect:

log ('a' + 2); // 'a2'

log ('4' + 3); // '43'

log ('five' - '4'); // NaN (not a number)

log (- '1'); // -1

log (1 + true); // 2

log (1 == true); // true

log (1 === true); // false

## Use position: fixed

Using this method may seem tempting for two reasons:

    No calculations are required for the header of the table, because the fixed element is outside the physical page and will remain in place.

    We avoid slow calculations because the fixed elements chase the table and do not stick with it, because we do the calculation in fixed periods (via throttle) and therefore it will appear that the fixed element is unresponsive and therefore not normal.

If the table width exceeds the permissible width and it becomes necessary to add a scroll, a header will not append the content on the horizontal axis because it is fixed on the page.
