# 引言

几年前，在我开始使用 PHP 之前，我使用 C 语言创建动态网页。这与当时提供的其他选项其实并不相似，尽管现在看来这几乎是不可想象的。创建一个动态页面意味着从你的脚本输出 HTML，并在需要进行任何更改时重新编译该脚本。PHP 提供的功能是在页面的任何需要的地方嵌入服务器端脚本。这是一个巨大的改进，意味着你可以像编写 HTML 一样编写 HTML 代码，并在需要时插入脚本。引入更改变得简单得多，而且由于 PHP 是一种解释型语言，因此不需要重新编译。

使用 PHP 的路径很多且多样，但坚持使用它的最重要原因是易于使用。这是 PHP 成为如此流行的 编程语言的主要原因。随着版本 5 的到来，PHP 再次为 Web 开发人员简化了生活。现在，你可以将一种强大但又不复杂的面向对象（OO）语言的力量加入到你的 Web 开发工具箱中。

## 面向对象适用于大型软件公司

反对 OOP 的另一个论点是：OOP 是最好留给大型公司使用的。如果有多个程序员参与同一个项目，那么面向对象的方法是一种必要的恶，但对于独立开发者来说，它并没有太大用。因为大型公司有许多从事某种程度专业化工作的程序员，因此需要使用面向对象的方法。这并不是独立开发者需要担心的事情。独立开发者需要与他人协调工作，因此过程化方法是更好的选择。

这种观点正确地指出了面向对象的方法更具模块化，因此更适合需要协作的环境。同样的是，在某些情况下，单个开发者可以完成更出色的工作——厨多不烂。而且，面向对象的方法可能会减慢开发速度这可能也是正确的。但面向对象的解决方案比过程化的解决方案花费的时间仅在第一次创建解决方案时更多。独立开发者可以像任何大型软件公司一样，从面向对象解决方案的可重性和适应性中获益。

## 顺其自然

我们已经讨论了反对在 Web 开发中使用面向对象方法的合理论点，但在很多情况下，起作用的是对改变的抵触。PHP 作为一种过程化语言非常成功。如果没坏，为什么要修？

计算机语言就像它们的自然界对应物一样，必须跟上环境的变化，否则将面临过时的风险。OOP 并不要求过程化编程，也没有使其过时。面向对象的方法也不总是正确的方法，正如某些 OOP 热衷者可能让你相信的那样。然而，某些问题需要面向对象的解决方案。此外，如果没有对 OOP 基础的基本了解，你就无法充分利用 PHP 5 的功能。例如，如果你想创建一个 SOAP 客户端，除了使用 SOAP 客户端，没有其他方法可以实现。

并没有要求你从面向对象的方法开始编程——这是你自己的选择。PHP 是一门赋予了面向对象能力的混合语言。你可以在需要时使用面向对象的方法，其他情况下回到过程化编程。

## 增加复杂性

对 PHP 变得过于复杂的恐惧，往往是针对面向对象 PHP 的更含蓄的反对。毫无疑问，OOP 有时会引入不必要的复杂性——只需看 C++ 的多继承或企业级 Java（Enterprise Java）即可。在 PHP 中并没有这种情况，而且有充分理由它不会发生。PHP 首先是一门 Web 开发语言（这就是为什么 PHP 采用面向对象方法花费了很长时间）。Web 编程是编程的一种特殊形式，引入面向对象能力是为了这一目的。PHP 对 OOP 的实现并不总是让 OOP 纯主义者满意，这说明了这一点。即使作为一种过程化语言，PHP 从来不是为了美观或成为模型语言；它一直是为了解决 Web 问题。

快速了解 PHP 的文化就应该让你信服，PHP 不可能发展成为一种过于复杂的语言。

PHP 是目前最受欢迎的 Web 开发语言，其成功的主要原因是易于使用。这并非偶然，它之所以易用是因为它被设计为一门简化 Web 开发的语言。在 PHP 升级为真正的面向对象语言后，这一点并没有被忘记。例如，PHP 5 引入的新类之一就是名副其实的 Element。使用这个类，你只需要四行代码就可以将 RSS 馈整合到页面中（见第 12 章）。

## 面向对象编程的基础

![](img/c8663459ed20)
本章面向不熟悉 OOP 基础概念的读者。我们将提供 PHP 中 OOP 实现的概述；我们将讨论面向对象的三个方面：类、访问修饰符和继承。尽管 OOP 可能是一种不同的范式，但在许多方面，我将使用过程化编程的示例来解释。

### 类

没有对象就没有 OOP，而这正是类所提供的。在最简单的层次，类是一种数据类型。然而，与整数、浮点数或字符等基本数据类型不同，类是用户定义的数据类型。类类似于记录，它封装了对象的特征。例如，一个人员（Person）记录可能包含出生日期、地址、姓名和电话号码。类是一种由其他数据类型组成的数据类型，共同描述一个对象。

### 与记录的区别

虽然类类似于记录，但一个重要的区别是类同样具有功能。而且，当函数成为数据类型的一部分时，过程化编程被彻底颠倒了，正如下面的示例语法所示。函数调用看起来像这样：

```php
function_call($somevariable);
```

在 OOP 中看起来像这样：

```php own$variable->function_call();
```

这里的显著区别在于，OO 变量本身并不要做事情；它们是执行者而不是被执行者，正因如此它们被认为具有行为。类的行为是其函数的总和。



在整数概念与具有特定值的特定变量 `sx` 之间。在继承的语境下，类作为对象的模板这一概念变得更加清晰，特别是当我们讨论多重继承（我们稍后会处理这个话题）时。

# 对象需要访问修饰符

OOP（面向对象编程）的实现是通过使用类的简单概念，将其作为特性和行为的凝聚整体——正如你在第 3 章中看到的，这正是 PHP 4 中对象的正品形态——但任何面向对象语言最重要的特性之一就是使用访问修饰符。访问修饰符通过控制对象的使用或重用方式来精炼对象模型。简单来说，访问修饰符对于你对对象可以做什么和不能做什么提供了指导。为了理解这意味着什么，让我们来看一个过程化编程的例子。

我们将子程序（subroutine）定义为从不被直接调用、仅由其他函数调用的函数。假设你是一个过程化程序员，拥有一组供其他几个程序员使用的函数和子程序库。如果能将子程序标记为次要的，对于指导他人如何使用你的库很有帮助，但目前唯一的方法是通过文档文档。然而，在 OOP 中，访问修饰符不仅指示了某些函数相对于其他函数的优先性，而且在程序上强制执行了这一点。它们实现了语言限制，确保“子程序”永远不会被直接调用。构造良好的类是自成文档且自我调节的。

在上述描述的情况下，对代码库进行文档记录的需求是因为它在协作环境中使用；具体的情况导致了访问修饰符的存在。OOP 的假设之一是它在一个交互式语文中进行，访问修饰符定义了交互方式。这是 OOP 和过程化编程之间的重要区别之一。访问修饰符为使用类提供了规则，而这种在语法上定义的“礼仪”通常被称为接口（interface）。通过提供接口，减少了对文档和对用户程序员“做正确的事”的依赖。

对代码库进行文档记录很重要，因为库会被重用；访问修饰符促进重用的原因完全相同——即为了促进重用。

# 对象重用与继承

从生物学意义上说，孩子继承父母，这些遗传物质决定了孩子的外观和行为。在 OOP 中，继承的含义是类似的——它是传递特性和行为的能力。OOP 的这第一个特性可能看起来有些魔幻，但实际上继承只是一种重用代码的技术——就像你可能会过程化编程中包含一个函数库一样。

如果你发现一个完全符合你需求的类，你可以直接使用它并从预定义的行为中获益。当一个类没有完全按照你的要求时，继承就派上用场了。这种情况向现有代码库添加函数并没有太大区别。通过继承，你可以利用现有的行为，同时赋予你所需的额外能力。例如，如果你知道需要创建一个蓝松鼠（Blue jay）类但目前尚不存在，你可以继承一个现有的鸟（Bird）类来使用它，然后对其修改以适应你的特定情况。

当一个类形成新类的基础时（例如 `Bird` 类作为 `Blue jay` 类的基础），原始类通常被称为基类（父类）。出于显然的原因，从另一个类派生的类被称为派生类（derived class）或子类。

# 多重继承

在自然界中，多重继承是常态，但在 OOP PHP 世界中，一个对象只能有一个父类。PHP 的创建者拒绝了类的多重继承想法。为了了解为什么，让我们再次使用 `Bird` 类来展示什么是多重继承以及它如何导致问题的。如果你想创建一个大顶（whooping crane）类，将该类派生自 `Bird` 类是合理的。假设你还有一个“濒危物种”（Endangered species）类。多重继承允许你通过这两个类的组合创建一个大顶类。在没有意识到这两个类都定义了进食行为之前，这似乎是一个极佳的主意。你应该倾向于哪一个？这种尴尬的情况凸显了多重继承的缺点。使用单继承，这种情况永远不会发生。

# 鱼和熊又要兼得

单继承提供了一种更简单、更直接的方法，但有时你可能希望结合来自不同类的行为。大顶鸟既是鸟又是濒危物种。每当你想要这种组合时，从零开始构建其中一个类是没有意义的。是否有一种方法可以组合不同的类并避免行为重叠的问题呢？

PHP 通过引入接口的概念解决了这个问题。在这种语境下，接口意味着一个没有数据成员的类，它仅由缺失实现的函数组成（没有函数体的函数原型）。任何继承自接口的类必须实现缺失的函数体。如果 `Endangered species` 是一个接口而不是一个类，那么拥有多个进食函数就无所谓了。`Bird` 类中的方法定义将作为接口函数的实现。通过这种方式，接口避免了重复定义相同函数的问题。

由于 PHP 不需要原型（prototyping），你可能对这个概念并不熟悉。函数原型是在在使用之前对函数名和参数的声明——如果你愿意，可以称为函数签名（function signature）。

一个类只能继承一个类，但由于接口缺乏实现，可以继承任意数量的接口。以真正的 PHP 风格，有助于构建一种强大但灵活的编程语言。（你将在第 10 章看到实用的接口，在那里我们将内置接口 `Iterator` 添加到数据库类中）。

接口可以被描述为抽象的，因为它们总是需要实现。因为它们是抽象的，接口比类更像模板。与类不同，它们永远无法被“原样”使用；它们只在继承的语境下才有意义。因为接口缺乏实现，它们只能作为创建派生类的模型。

# 接下来的路

我们触及了 OOP 的三个核心话题：类、访问修饰符和继承。类定义了对象，访问修饰符决定了如何使用对象，而继承使得对象能够适应不同的情况。我强调了过程化编程与 OOP 的相似之处，旨在缓解向面向对象方法的过渡。像类这样包含函数的数据类型在过程化编程中是未过的。此外，OOP 提供了访问修饰符来控制对象的使用。OOP 不再依赖文档和严谨的方法，而是将限制整合到了语言中。

下一章讨论 PHP 4 和 PHP 5 之间的差异。对于已经熟悉 PHP 4 面向对象能力并想要改进概述的人来说，这将特别有用。



对对象的支持已经植入了语言中——你可以选择使用对象，也可以简单地回到过程化编程。PHP 是一种混合语言这应该被视为积极因素，而不是劣势。在某些情况下，你可能只想插入一段 PHP 代码，而在另一些情况下，你将希望利用对象（OO）的能力。

正如我在第 1 章中所述的，在某些情况下，面向对象的解决方案是唯一的解决方案。PHP 5 承认这一事实并引入了完整的对象模型，巩固了 PHP 作为顶级服务器端脚本语言的地位。

# 异常

所有的 OOP 语言都支持异常，这是面向对象处理错误的方式。为了使用异常，我们需要 `try`、`catch` 和 `throw` 关键字。`try` 块封装可能导致错误的代码。如果发生错误，它会被抛出并被 `catch` 块捕获。异常相对于错误的优势在于，异常可以集中处理，从而使代码更加清晰。异常还显著减少了你需要编写的错误捕获代码，这为这项枯燥的任务带来了欢迎的缓解。此外，拥有内置的异常类使得通过继承创建自定义异常变得非常容易。（你将在第 79 页的“用异常替换错误”部分中学习如何从错误捕获过渡到异常处理。）

## PHP 5 的采用

由于 PHP 5 已经不再是尖端技术，它已经发布了一年多，并且有了许多错误修复。它是一个稳定的产品。在开发者可以控制服务器配置的情况下，毫无疑问，升级到 PHP 5 将是有益的。但开发者在这些问题上并不总是有选择。在某些情况下（例如开发者无法控制 Web 托管），升级的决定掌握在别人手中。

PHP 是其自身成功的受害者。PHP 4 的流行和稳定减缓了 PHP 5 的采用速度。PHP 5 是一门成熟的语言，支持许多应用程序（无论是开源或其他类型）。人们自然不愿扰动现状。由于这个原因，PHP 5 的采用过程较为缓慢，特别是在共享主机环境中。

其他托管选项采用 PHP 5 的速度快得多。各种私有服务器（VPS）托管选项通常包含 PHP 5，专用主机也是如此。作为一种更安全且日益廉价的托管方案，VPS 变得越来越流行。

## 妥协

PHP 5 的广泛采用迟早会发生，但本书意识到，开发者可能至少在一段时间内仍需要继续编写在 PHP 4 下运行的应用程序。因此，在任何地方，PHP 5 版本的代码都提供了对应的 PHP 4 版本。

# 升级到 PHP 5

如你所知，PHP 5 版本的重大变化是改进了对面向对象编程（OOP）的支持。在这方面，最重要的两个变化是引入了访问修饰符（access modifiers）和更改了类的构造语法。这两个变化都将对 `DirectoryItems` 类产生影响。

## 访问修饰符

除了类概念之外，访问修饰符可能是对象语言最重要的特性之一。修饰符的主要用途是描述和限制数据成员及方法。我们本章关注的修饰符是 `public`（公共）和 `private`（私有）。`private` 修饰符用于修改或描述与类内部行为相关的事。`public` 修饰符用于描述类的外部行为，或者如果你愿意的话，描述类的接口。

至于 `DirectoryItems` 类的语法更改，这意味着将关键字 `var` 替换为 `private`，因此：

```
var $filearray = array();
```

变为：

```
private $filearray = array();
```

正如你记得的，$filearray$ 是 `DirectoryItems` 类唯一的数据成员。在大多数情况下（静态类外，我们将在第11章讨论），你应该将所有数据成员设为 `private`，因为通过这样做，你通过限制对数据的访问来保护数据的完整性。

为了更好地理解访问修饰符，将数据成员或实例变量想象成数据库中的数据是有。为了维护数据库中数据的完整性，限制访问并限制添加或更改数据的方式是明智的。程序员可能会编写一个良好的应用程序来实现这一结果，要求用户登录并对数据格式化的方式实施控制。例如，你可能希望数据以特定格式存储，并通过使用掩码文本框强制执行这种格式。

由于 PHP 4 中不存在访问修饰符，更改变量的值只需要一次赋值。你可以在此处修改 $filearray$ 变量：

```
$di->filearray[0] = "anyfile.jpg";
```

这样做有一个缺点，因为对 $filearray$ 的更改没有被控制，允许直接访问数据成员会极大地增加污染你数据的风险。如果你使用 `private` 关键字，直接访问将不再可能。

根据前面的数据库类比，将实例变量设为 `private` 意味着允许通过程序员的应用程序或前端访问数据。

但等一下，这是代码，对吧？你不会不恰当地修改它，所以为什么要关心呢？因为面向对象编程假设其他程序员可能会使用你的代码，反之亦然。

Bruce Ekel 将此称为程序员使用由类创建者创建的对象。即使你是一个独立开发者且不指望其他程序员使用你的代码，访问修饰符仍然是一个重要的保护。为什么？你曾多少次回到自己的代码（即使只离开了很短一段时间），却发现难以准确判断你正尝试实现什么？显然，在这种情况下，尽管你是发源者，但你同时也是一个客户端程序员。访问修饰符的使用强制程序员显式地表达他的意图。如果某个特定的数据成员或方法涉及类的内部行为，应用适当的访问修饰符就记录了这一意图。至少，我们都需要访问修饰符来保护我们的代码不受那个最自以为是的客户端程序员——我们自己。

```php
public function checkSpecificType($extension) {
```

列表 5-2：`checkSpecificType` 方法

但在现实世界中，通常并不整洁。目录通常包含多种文件类型。如果你调用 `checkSpecificType` 方法并且它返回 `false`，你就需要过滤目录，这就是列表 5-3 代码的作用：

```php
public function filter($extension) {
  $extension = strtolower($extension);
  foreach ($this->filearray as $key => $value) {
    $ext = substr($key,strpos($key, ".")+1);
    $ext = strtolower($ext);
    if ($ext != $extension) unset($this->filearray[$key]);
  }
}
```

## 内部行为——私有方法

你已经见过私有数据成员，但在这里你遇到了你的第一个私有方法。私有方法与类的内部工作有关，只能从类内部调用。执行图像缩小的方法（见列表 6-2）是一个私有方法——`createThumb`——它是从构造函数中调用的。

```php
private function createThumb($thumbnail) {
//array elements for width and height
$srcW = $this->imageproperties[0];
$srcH = $this->imageproperties[1];
//only adjust if larger than max
if($srcW > $thumbnail || $srcH > $thumbnail){

//get proportions
$desW = $srcW/$reduction;
$desH = $srcH/$reduction;
$copy = imagecreatruecolor($desW, $desH);
imagecopyresampled($copy,$this->image,0,0,0,0,$desW,$desH,$srcW,$srcH) or die("Image copy failed.");
    //destroy original
imagedestroy($this->image);
    $this->image = $copy;
}
}
```

列表 6-2：createThumb 方法

在此列表中，`createThumb` 检查图像的宽度和高度，以判断其是否大于目标尺寸。如果是，该方法会创建一个缩小后的副本并用副本覆盖原始图像。
这个用于图像缩小的私有方法从构造函数中调用，并且只能从类中调用。通过在构造函数内部调用它，就不需要直接调用，客户端程序员受益于在构造后立即获得一个完全形成且可用的对象。

## 它必须是私有的吗？

假设你的意图是对同一张图像进行多个不同尺寸的缩小处理，就像摄影师为同一张照片制作不同尺寸的副本一样。在这种情况下，保存原始图像并将 `createThumb` 方法设为公共可能是合理的。这样，可以通过反复调用此方法并传递不同的值来创建不同尺寸的图像。

事实上，只需对代码和接口进行极小的更改，你就可以让你的类适应这种场景并仍然其原始意图。

## 辅助方法

### 公共方法

紧随构造函数之后的是另一个名为 `__destruct` 的公共方法。方法前的双下划线 `__` 被称为析构函数。函数名称表明该方法与构造函数一样是另一个魔术方法。再次，它是 PHP 5 新引入的方法。（回想第 5 章，魔术方法会在后台发生，就像魔法一样。）

```php
public function __destruct(){
    if(isset($this->image)) {
        imagedestroy($this->image);
    }
}
```

虽然析构函数在 PHP 是新的，但任何熟悉其他 OO语言的人可能都遇到过它们。正如其名称所示，析构函数是构造函数的相反。构造函数初始化对象，而析构函数释放类可能分配的资源。通常，PHP 很好地完成了清理工作，因此析构函数往往是必要的。在这里用于确保图像资源被释放。

## 垃圾回收

像 Java 一样，PHP 使用垃圾回收自动清理资源。因为程序员不需要分配和释放内存（就像在 C++ 等语言中），自动化程序必须释放资源。垃圾回收确定对象何时不再使用并处理它们，例如当它们超出范围时。然而，使用析构函数可以作为加速垃圾回收。在 ThumbnailImage 类的情况下，析构函数通过调用 `imagedestroy` 函数释放图像。

你可以直接调用析构函数，但对于其他魔术方法，析构函数设计为在没有程序员干预的情况下后台调用。

# 7 构建 PAGENAVIGATOR 类

当目录中包含大量图像时，将它们所有的图像都显示在一个网页上是不理想的，因为这可能会创建一个非常大且冗长的页面。网页的长度应该是合理的，且下载时间不应该太长。与其将所有图像都倾倒在一个页面上，不如使用分页器按顺序方式浏览它们。本章将承担创建分页器类的任务；第 8 章将配合该类。

在创建分页器之前，你需要确定它的行为。保持其设计的灵活性，并确保其外观是可以配置的，以便与页面的风格融合。

## 分页器将如何运行？

一个很好的起点是查看 Google 底部的分页器。在搜索 Google 时，默认设置每页显示 10 条结果，分页器出现在页面底部。通过点击“上页”或“下一页”链接、选择页码或点击 Google 中的许多数字来导航。如果你的查询返回了大量页面，分页器并没有显示所有页面。记录按相关性排序。由于这种排序方案，跳转到最后一页的动力不大，实际上并没有简单的方法可以做到。

## 不同类型的搜索

在很多情况下，搜索返回的项目较少，且记录通常按字母排序。在这些情况下，应该有一种简单的方法跳转到开头和结尾页，除了可以点击“上页”和“下一页”。在 Google 中，能够配置每页显示的项目数也是必要的。

你还应该通过分页器限制同时显示的页数或链接数，以适应不同的需求和情况。例如，如果你有 2000 个项目要显示，且每页显示 10 个，可能不建议在页面底部显示所有链接。但同时，应该显示总页数并识别当前页，这样用户就不会感到困惑。

最后，导航按钮的显示样式可以是配置的，以匹配网页的设计。实现此点的最佳方法是为它们分配类名，并使用样式表（CSS）处理它们的样式。

## 异常处理 (Ain't Misbehavin’)

如果你希望你的导航器正常工作，可以检查传递给构造函数的某些值；这正是 `checkRecordOffset` 方法的作用。如果它返回 `false`，则将终止对象的构造。让我们来看：

```php
private function checkRecordOffset($recordoffset, $recordsperpage) {
    $bln = true;
    if($recordoffset%$recordsperpage != 0) {
        $this->errorstring = "Error - not a multiple of records per page";
        $bln = false;
    }
    return $bln;
}
```

传递给构造函数的 `checkrecordoffset` 变量告诉导航器当前的位置。由于你在保持每页显示数量的同时对列表进行分页，因此记录偏移（record offset）必须是每页显示数量的倍数。如果不是，导航器可能仍运行，但其行为将变得不稳定。由于此原因，会设置错误消息变量，返回 `false` 并终止应用程序。终止应用程序并识别原因可以避免调试运行异常的程序。

## 确定总页数

由于你的导航器始终允许你跳转到最后一项，你需要知道总页数：

```php
private function getTotalPages($totalrecords, $recordsperpage) {
    $this->totalpages = ceil($totalrecords/$recordsperpage);
}
```

你使用 `ceil` 函数进行向上取整，因为最后一页可能是部分页面。例如，如果每页有 101 个项目，前 10 页每页显示 10 个，而第 11 页只显示一个。

## 确定当前页

除了总页数外，你还需要知道当前页，因此必须计算一个 `calculateCurrentPage` 方法：

## 类感知型变量

传递给构造函数的参数是使用 PHP 内置函数 `mysql_connect` 建立数据库连接所必需的。同样，这个方法是一个包装方法，但多了一些额外的花哨功能。

```php
public function __construct($hostname, $username, $password) {
    if(MySQL::$instances == 0) {
        $this->connection = mysql_connect($hostname,$username,$password) or
        die (mysql_error() . " Error no: ".mysql_errno());
        MySQL::$instances = 1;
    }else{
        $msg = "Close the existing instance of the " .
        "MySQL class.";
        die($msg);
    }
}
```

如果已经存在实例，则该类将不会被实例化。如果 `$instances` 变量值为 0，则与服务器建立连接，并将此静态变量的值设置为 1。检查此静态变量的值是有意义的，因为它在所有实例之间共享，对所有实例可用，且对所有实例都是相同的。

引用静态变量的语法与引用普通数据成员的语法不同。使用伪变量 `$this` 配合 `$instances` 是没有意义的，因为静态变量属于类而不是特定实例。简单来说，就是使用类名，并将箭头 `->` 替换为双冒号 `::` ——即作用域解析符。

作用域解析符主要用于引用静态数据成员或静态方法。在第 10 章中，你将看到该运算符的两种用法，但现在你只需要关注它在静态数据成员上的用法。在类内部引用静态变量时，你也可以选择将类名替换为关键字 `self`。在这种情况下，表达式 `self::$instances` 等同于 `MySQL::$instances`。在类范围之外引用静态成员必须使用类名。你在这里不需要担心这一点，因为 `$instances` 是私有的，无法在 `MySQLConnect` 类之外引用。

此时你可能在想：“这听起来很好，但为什么要想要一个只能创建一个实例的类呢？”建立数据库连接是一个昂贵的操作，因此限制连接的创建可以节省资源。

通过将连接类限制为单例，我们正在模拟内置的 `mysql_connect` 函数。它的默认行为是重用连接资源而不是创建一个新连接。

然而，在某些情况下，新连接是必要的。

## 其他连接

如果一个脚本需要连接两个不同的服务器，就需要两个连接对象。`close` 方法使得连接到不同的服务器成为可能。

```php
public function close() {
    MySQLConnect::$instances = 0;
    if(isset($this->connection)) {
        mysql_close($this->connection);
        unset($this->connection);
    }
}
```

MySQLConnect可以存在两个实例，但不能同时存在。如果你想建立另一个服务器的连接，必须先关闭现有连接。`close` 方法关闭当前连接并将静态变量 `$instances` 重置为 0。通过这样操作 `$instances` 变量，你可以创建一个新连接，但只能在当前连接关闭之后。

显式关闭连接并取消它，是为了在你不小心在关闭连接后创建结果集方法时，能够提供更清晰的错误信息。关闭当前连接的要求也提醒了我们，结果集是一个依赖对象。

为了让这一点更加清晰，让我们看看结果集是如何创建的。

## PHP 标准库 (SPL)

这些对 MySQL 类的计划更改使用了 PHP 标准库（Standard PHP Library，简称 SPL），这是一组旨在解决编程问题的类和接口集合。SPL 是 PHP 5 新引入的，大致可以与 C++ 中的标准模板库（STL）或 Java 语言中构建的许多类相比。但由于 Java 中有数千个类可以调用，而 PHP 中可用的类数量要少得多。

## 通过继承扩展类

OOP 的主要优势之一是你不必从零开始。现有的类可能已经为你完成了工作。如果一个现有类恰好实现了所需的功能，你就可以原样使用它。如果它实现的功能相似，但不是完全符合你的需求，你就可以对它进行适配。这种适配过程被称为继承。

继承是面向对象（OO）语言最重要的特性之一。它允许我们从现有类创建新类，利用已经定义的行为并根据需要对其进行调整。“继承”一词是恰当的，因为原始类的数据成员和方法变成了新创建类的一部分。然而，遗传继承不同，子类在某些方面可能与父类相似，但在其他方面则不同。

由于子类派自父类，它也被称为派生类（derived class），而它的父类被称为基类（base class）。父类有时也被称为超类（superclass），派生类称为子类（subclass）。

你会注意到一些不熟悉的关键字（如 `protected` 和 `final`）以及几个以双下划线开头的陌生方法（魔术方法）。我们将逐一讨论这些内容。

### protected

你应该对应用于数据成员或方法的关键字 `private` 和 `public` 应该有良好的理解（如果没有，请参第 4 章）。然而，到目前为止关于访问修饰符的另一个额外信息是：`private` 方法或数据成员不会被派生类继承。

但在某些情况下，你可能希望新类继承 `private` 数据成员。为了实现这一点，你使用访问修饰符 `protected` 来代替 `private`。`protected` 数据成员像 `private` 成员一样不能在类外部直接访问，但它可以被派生类继承并直接访问。在所讨论的具体情况下，任何派自 `Exception` 的类都将直接访问 `$message`、`$code`、`$file` 和 `$line`，但无法直接访问 `$string` 或 `$trace`。这意味着在派自 `Exception` 的类内部允许赋值：

```php
$this->message = 'New Error';
```
而这种操作是不允许的：

```php
$this->string = 'Any string';
```

除了限制访问和控制客户端程序员使用类的方式外，`private`、`protected` 和 `public` 关键字在继承中也起着作用。`protected` 方法和数据成员会被派生类继承，但受限制的访问权限会被保留。

### final

关键字 `final` 也仅在继承的上下文中具有意义。
当一个方法被定义为 `final` 时，任何派生类都不能更改它。对于非 `final` 方法，派生类可以重新定义函数并产生不同的结果。派自 `Exception` 类的类不能创建新的 `getCode` 方法。另一方面，创建派生方法 `__toString` 则没有任何限制。

> 从类的创建者的角度来看，关键字 `final` 是一种确保类的中某些元素不被更改的方法。此外，当 `final` 应用于整个类时，该类中的任何内容都无法被更改。

# 魔术方法

`Exception` 类包含两个新方法。我们将逐一讨论它们。

### __toString

如果类定义了 `__toString` 方法，那么每当该类被显示时，它就会被调用。例如，假设你创建了一个 `Exception` 实例并显示它：

```php
$se = new Exception();
echo $se;
```

显示变量的预期结果显而易见的。然而，如果没有定义 `__toString` 方法，你会看到类似 Object 的内容。`__toString` 方法的引入是为了控制对象的字符串表示。它被称为“魔术”，是因为它每当类被显示时都会自动调用。（我们将在本章稍后讨论此方法。）

## __clone

`__clone` 方法稍微复杂一些。它允许你在使用拷贝运算符复制对象时，调整对象的行为。该运算符（PHP 5 新引入）允许你创建一个对象的副本而不仅仅是它的引用。（对于熟悉其他 OO 语言的人来说，魔术方法类似于构造函数）。

你应该对任何作为聚合对象的类实现 `__clone` 方法。聚合对象是指至少有一个数据成员本身也是对象的。例如，如果 `Player` 和 `Team` 都是对象且包含 `Players`，那么 `Team` 就是一个聚合对象。

注意：请参阅第 13 章关于 `clone` 方法和 `clone` 运算符的更详细描述，以及对聚合类的深入处理。

```php
        }else{
            $message = __CLASS__" - " . $message;
        }
        //调用 Exception 构造函数
        parent::__construct($message, $errorno);
    }

    //重写 __toString()
    public function __toString(){
        return ("Error: " . $this->code . " " . $this->message);
    }
}
```

## 捕获异常

你已经完成了数据库类中所有与异常相关的更改。你只需要看到通过将代码封装在 `try` 块中来捕获异常。

`try` 块是一种编码可能导致错误的编程结构。它后面总是跟着一个 `catch` 块。在 `try` 内部发生的错误（更准确地说说是异常）会被抛出并由 `catch` 处理。这就是为什么说 `try` 块处理异常。

然而，错误捕获和异常处理之间存在重要的区别。`catch` 子句的参数始终是一个对象。在 `try` 块作用范围内发生的任何 `Exception` 都会锁定一个具有匹配异常类型作为参数的 `catch`。

> 在 `catch` 块中对对象的识别被称为类型提示（type hinting）。我们将在第 11 章详细讨论这一点。

你应该在可能抛出异常的第一行代码之前立即开始 `try` 块（即我们创建连接对象的地方）。然后是 `try` 块内的后续每行代码，`catch` 块除外。代码与其他与第 9 章文件下载包含的 `page.php` 文件中的代码相同；仅在列表 10-5 中重现了相关部分。

```php
try{
    $con = new MySQLConnect($hostname, $username, $password);
    //所有剩余代码
}
catch(MySQLException $e){
    echo $e;
    exit();
}
catch(Exception $e){
    echo $e;
    exit();
}
```

被抛出的异常会在代码块中寻找第一个匹配的异常类型。当找到匹配项时，它会执行该块中的代码。它会忽略所有的 `catch` 块（除非异常被重新抛出）。例如，如果在列表 10-5 的 `try` 块中抛出一个 `SQLException`，它将被第一个 `catch` 捕获，而第二个 `catch` 中的代码将不会执行。

`catch` 块的顺序是继承关系的反序：如果父类的 `catch` 块排在子类之前，异常将始终被父类捕获，导致子类无法被访问。

当使用过程化错误处理时，你必须在可能引起问题的代码之后立即检查错误。如列表 10-5 所示，`Exception` 的捕获位置可能距离问题发生的地方很多行之外，这是一个优势，因为它使得代码更具可读性和可维护性。

## 实现接口

继承一个现有的类是 OOP 程序员兵器库中一个非常强大的工具。然而，这并不总是合适的选择，因为 PHP 不允许一个类拥有多个父类。

这通常看起来是一件好事；它避免了多重继承可能引入的复杂性。然而，假设你创建了一个更抽象的数据库结果集，并从它定义了你的 `MySQLResultset`。使用单继承意味着你的类将无法继承任何其他类。

出于这个原因，PHP 允许多重继承，但仅针对接口。正如你在第 2 章中看到的，接口是一个没有数据成员的类，它声明但不定义方法（这些方法留给派生类来实现）。接口像一个骨架，而实现类提供主体。虽然一个类只能有一个父类，但它可以实现任意数量的接口。

列表 10-6 显示了我们想要改进 `MySQLResultSet` 类的代码：`Iterator`。

```
interface Iterator{
    public function current();
    public function key();
    public function next();
    public function rewind();
    public function valid();
}
```

列表 10-6：`Iterator` 接口的方法。与 `class` 关键字不同，`Iterator` 以 `interface` 开头，但在其他地方看起来像一个类。注意方法名具有访问修饰符，且方法声明后跟着分号。方法名后没有大括号，因为没有实现——这恰恰是接口的本质。接口是一个骨架；实现类必须填充它。

## 学习 Iterator 接口

以下是 `Iterator` 接口中每个方法的简要描述：

- current | 返回当前元素
- key | 返回当前元素的键
- next | 移动到下一个元素
- rewind | 将迭代器重置到第一个元素
- valid | 检查在调用 `rewind` 或 `next` 后是否存在当前元素

通过观察迭代器的实际运行可以获得更多信息。例如，列表 10-7 中的代码使用 `Iterator` 接口中的所有方法遍历了一个可迭代对象。

```
$iterator->rewind();
while($iterator->valid()){
    echo $iterator->key();
    print_r($iterator->current());
    $iterator->next();
}
```

列表 10-7：使用 `Iterator` 接口中的方法遍历可迭代对象

你首先通过调用 `rewind` 方法来确保处于结果集的开头。对 `valid` 的调用控制了 `while` 循环，使其仅在还有其他记录可以检索时才继续执行。在我们的实现中，`key` 方法返回的键将是一个数字；显示它仅用于演示之目的。`current` 方法返回结果集当前指向的记录。最后，调用 `next` 移动指针。

你已经在许多不同情况下正确地使用了循环（很可能是针对数组），但你可能没有深入考虑过后台发生了什么。列表 10-7 显示了 `foreach` 循环中发生了什么。在循环开始时，会隐式地调用 `rewind` 方法，确保你处于开头且第一条记录已准备好显示。如果存在有效记录，你可以带有指向当前行的记录指针进入循环。然后记录指针会向前移动——通过隐式调用 `next`——并重复此过程直到到达记录集的末尾。

## 迭代器方法

我们很少直接使用迭代器方法。实现这个接口是为了可以在 `foreach` 循环中使用 `MySQLResultSet`。在某种意义上，这些方法是“神奇的”，因为它们由 `foreach` 结构在后台被调用，就像当 `MySQL` 对象被销毁时 `MySQL` 类的方法被调用的方式一样。在 `foreach` 循环中使用的任何对象都必须设计自己的迭代器方法。实现将与结果集迭代器大不相同，但所有实现特定接口的对象都会表现出共同的行为。接口的意义在于，它保证了特定方法的存在，而不规定它们应该做什么。

## 实现

要实现接口，你需要在类中指示明。继承类时使用 `extends`，但继承接口时使用 `implements`。

```
class MySQLResultSet implements Iterator
```

实现接口还需要在现有类中添加 `currentrow`、`valid` 和 `key`。`currentrow` 成员将持有当前行的值。`valid` 是一个布尔值，指示是否存在当前行。`key` 成员仅作为下标。

## 五个新方法

从 `Iterator` 继承的前三个方法是简单的访问器方法，返回新添加的成员，如下：

```php
public function current() {
    return $this->currentrow;
}

public function key() {
    return $this->key;
}

public function valid() {
    return $this->valid;
}
```

`current` 方法在存在记录时返回当前记录的值；`key` 返回其下标；`valid` 除非记录指针位于结果集的末尾。然而，更有趣的方法是 `next` 和 `rewind`。首先我们看 `next` 方法：

```php
public function next() {
    if($this->currentrow = @mysql_fetch_array($this->result)) {
        $this->valid = true;
        $this->key++;
    } else {
        $this->valid = false;
    }
}
```

在代码中，你看到 `next` 尝试从结果集中检索下一行，并相应地设置数据成员 `valid` 和 `key`。

正如你预期的，`rewind` 在首先检查行数大于 0 后，将指针重置到结果集的开头。该方法还维护 `valid` 和 `key` 成员。`key` 被重置为 0。这里是该方法：

```php
public function rewind() {
    if(@mysql_num_rows($this->result) > 0) {
        if(@mysql_data_seek($this->result, 0)) {
            $this->valid = true;
            $this->key = 0;
            $this->currentrow = mysql_fetch_array($this->result);
        }
    } else {
        $this->valid = false;
    }
}
```

该方法之所以有效是因为你的结果集是缓冲的；它是使用 `mysql_query` 函数创建的。因为缓冲结果在内存中存储所有行，所以记录指针可以重新定位。

非缓冲结果使用单向游标，因此它无法使用 `mysql_data_seek` 函数。




当我引入接口时，我将它们定义为拥有方法但没有方法体的类。实现接口的类必须为接口的每个方法提供主体。那么，你该如何处理无缓冲结果集（unbuffered result set）和 `rewind` 方法呢？

就像无畏的鸟不飞行一样，无缓冲结果集可以定义一个什么都不做的 `rewind` 方法。

接口中存在不需要的方法并不是 PHP 特有的。Java 等其他面向对象的语言通过使用“适配器”类来规避这个问题，这些类为不需要的方法提供空实现，并仅要求定义所需的方法。

## 留有未定义的方法

如果你实现了一个接口但没有定义它的所有方法，你将收到一个致命错误消息。例如，如果你尝试在不定义 `key` 方法的情况下使用 `MySQLResultSet` 类，你将看到类似的致命错误：

```
Class MySQLResultSet contains 1 abstract methods and must therefore be declared abstract (Iterator::key);
```

这可能不是你预期的错误，但它仍然是一个错误，而且是一个启发性的错误。如你所见，尽管你实现了 `key` 方法，它并没有消失，因为它是继承自 `Iterator` 接口的。（`key` 方法被认为是抽象的，因为它没有实现。）

消除此错误消息有两种方法。显而易见的方法是定义 `key` 方法。然而，你也可以通过为类添加 `abstract` 修饰符（将 `MySQLResultSet` 声明为 `abstract class MySQLResultSet`）来创建无错误的代码。

你刚刚创建了自己的抽象类，抽象类是一个拥有一个或多个缺乏实现的类。纯抽象类是指所有方法都缺乏实现的类，就像接口中的所有方法一样。纯抽象类和接口之间的唯一区别在于，它被定义为一个类而不是接口。

你不能创建抽象类的实例；你无法像接口那样继承自它并实现抽象方法。你将在下一章节中学习抽象类的内容。

## 实现与访问

通过移除 `key` 方法并强制报错，我们又学到了更多关于 OOP（面向对象编程）的知识。让我们通过将 `rewind` 方法的访问修饰符从 `public` 改为 `private` 看看能学到什么。这样做并在浏览器中预览该类。

```
Access level to MySQLResultSet::rewind() must be public (as in class Iterator)
```

你不仅必须实现 `Iterator` 接口的所有方法，而且不能对这些方法的访问进行er限制。如果你仔细考虑，这非常有道理。`foreach` 结构需要一个 `public` 的 `rewind` 方法——它无法访问 `private` 的 `rewind` 方法。

然而，你可以放宽限制，因为这样做不会干扰你的实现中其他类的行为。例如，你可以将 `protected` 方法变为 `public`。（此规则适用于所有的继承情况，而不仅仅是接口。）

## 遍历 MySQLResultSet

在第 9 章中，你使用 `while` 循环和 `getRow` 方法遍历了结果集，如下：

```
while($row = $rs->getRow()) {
    echo $row[0]." - " . $row[1];
    echo "<br />\n";
}
```

由于你实现了 `Iterator` 接口，你可以使用 `foreach` 循环来遍历结果集。`while` 循环现在被替换为：

```
foreach($rs as $row) {
    echo $row[0]." - " . $row[1];
    echo "<br />\n";
}
```

如你所见，实现 `Iterator` 接口比创建一个适用于 `while` 循环的方法要困难得多。尽管这看起来像是费力不讨，但这种方法有其优势。例如，我们可以通过简单地启动另一个 `foreach` 循环来多次遍历记录集。记录指针会在后台重置，无需你执行任何操作。如果你使用原始代码，你将必须编写一个 `rewind` 方法，并在重复循环之前显式地调用它。

学习 `Iterator` 接口是极值得花费时间的的，因为许多内置类和接口都继承自这个接口。例如，有一个 `DirectoryIterator` 类——它是你在早期章节中开发的 `DirectoryItems` 的多功能替代品。

高级面向对象编程概念

之前的两个章节引入了许多新的面向对象编程（OOP）概念。为了清晰起见，某些主题进行了深入讨论，而另一些则一带而过。在这些章节的内容仍让你记忆犹新时，让我们回到一些简要提到过的话题，即抽象类、`static` 关键字的使用以及类型提示（type hinting）的影响。

## 抽象类

在第 10 章中，我们看到如果派生类没有实现接口的所有方法，那么它必须被声明为抽象的。让我们把这个概念推向极端，看看一个完全抽象的类是什么样的。列表 11-1 显示了此类类的定义。

```
abstract Bird {
    protected $plumage;
    protected $migratory;
    abstract public function __construct();
    abstract public function Fly();
    abstract public function sing();
    abstract public function eat();
    abstract public function setPlumage($plumage);
    abstract public function getPlumage();
    abstract public function setMigratory($migratory);
    abstract public function getMigratory();
}
```

列表 11-1：抽象类 Bird 的定义

正如第 10 章所看到的，任何包含抽象方法的类必须在类声明中包含 `abstract` 关键字。该类可以拥有任何数量的数据成员以及任何数量的方法。然而，如果方法缺少实现，它也必须被声明。

列表 11-1 中的类将数据成员声明为 `protected`，以便派生类可以使用。该类可以是纯抽象类，因为它的所有方法都是抽象的。注意，该类的所有方法都声明为 `public`。让我们看看为什么。

## 私有方法不能是抽象的

标识为抽象的方法不能是 `private`；它们必须是 `public` 或 `protected`。原因是抽象私有方法是自矛盾。因为抽象类具有未定义的方法，它无法被实例化（它只作为派生类的父类）。拥有抽象私有方法的类是可以实现的，因为私有方法无法继承。同样的理由也适用于抽象抽象方法。

> 记住 `final` 方法不能在派生类中更改。抽象方法不能是 `final`，因为它必须被重写——即更改。

没有定义成员的纯抽象类与接口有何区别？接口可以拥有数据成员或构造函数。（这在未来的 PHP 版本中可能会改变。关于允许接口拥有构造函数有一些讨论。）为了将列表 11-1 所示的 Bird 类转换为接口，你需要将关键字 `class` 替换为 `interface` 并移除 `$plumage`、 `$migratory` 和构造函数。虽然接口方法实际上是抽象的，但你仍然需要删除每个方法的 `abstract` 描述符。

## 接口还是纯抽象类？

你了解接口和纯抽象类的语法差异，但什么时候应该使用一个而不是另一个？通常，使用接口比使用纯抽象类更好，因为这种


接口的灵活性。PHP 不允许类的多重继承；子类可能只能有一个父类。然而，你可以实现任意数量的接口。

当具体方法和抽象方法混合时，使用抽象类更有意义。你可以在期望具有相同派生类行为的地方提供实现，也可以提供一个行为会不同的抽象方法。当然，你可以忽略那些期望派生类行为产生差异的方法，通过将方法声明为 `abstract`，你可以确保它在任何派生类中被实现。在后续关于多态的讨论中，这将如何利用这一优势。

## 多态

在第 10 章中，你通过继承 `Exception` 创建了一个 `SQLException` 类。类型提示允许你轻松区分不同类型的异常，并使得拥有多个 `catch` 块成为可能。然而在使用类型提示时，必须仔细安排 `catch` 块的顺序，以确保子类在父类之前。具体来说，`SQLException` 必须在 `Exception` 之前，因为 `catch` 块会捕获任何派生类。因为它派自 `Exception`，所以 `SQLException` 可以被 `Exception` 块捕获。父类可以代表其子类，但子类不能代表其父类。（这看起来像是一个缺点，但你会看到如何利用它的优势。）

## 控制函数的使用方式

类型提示可以赋予程序员对函数使用方式的更多控制。假设你根据列表 11-2 所示的 `Bird` 类定义了 `Canary`（金雀）和 `Lark`（百灵鸟）。你可以向列表 11-1 中的函数传递金雀或百灵鸟。

```php
function doSomething(Bird $b) {
  // 某些操作
  $b->sing();
  // 其他操作
}
```

列表 11-2：使用类型提示指定 `Bird` 对象的函数

尽管 `Bird` 类是一个无法实例化的抽象类，你仍然可以使用它对函数参数进行类型提示，这与 `catch` 块的类型方式相同。

在列表 11-2 中，类型提示禁止向函数传递 `bird` 以外的任何内容——传递任何其他对象或原始类型都会导致错误。通过这种方式，程序员可以限制函数的使用方式。你之前通过顺序正确的 `catch` 块使用了类型提示来捕获特定类型的异常。而 `doSomething` 函数则相反；它捕获任何类型的 `Bird`。这种在预先不知道具体类型的情况下，将任何类型的 `Bird` 传递给函数，并期望它能按预期方式运行的能力被称为**多态**。父类承担了子类的特征。

如你所知，PHP 是一种弱类型语言。多态需要像 Java 或 C++ 这样的强类型语言。在这些语言中，每当声明变量或将其用参数时，它都被声明为特定的数据类型。在 PHP 中，参数类型提示并没有定义数据类型，而是过滤接受的类型。对于列表 11-2 中的代码，$b 并没有定义 $b$ 的类型，它只是阻止了所有其他类型。如果是这样，那么 $b 就与其他任何 PHP 变量一样，没有特定类型。它是一个通过赋值变为类型的变体。事实上，你并没有一个能够执行任何子类方法的一等类，你拥有的只是子类本身。因此，PHP 是否支持多态仍有争议。

无论 PHP 是否真正支持多态，类型提示和抽象方法的结合都是一个强大的工具。前者保证了某种对象，后者保证了特定方法的实现。出于这些原因，你可以确保传递给方法的任何对象都会实现 `sign` 方法。抽象 `sign` 方法的声明确保了你不会得到一个不是鸟的类，而类型提示确保了只有鸟被传递给此函数。

除 `catch` 块外，在所有情况下，类型提示都是可选的。`catch` 中的变量数据必须指定，且它必须是 `Exception` 或派自 `Exception` 的类。类型提示仅适用于对象（尽管从 PHP 5.1 开始，数组也可以进行类型提示）。类型代码也具有自文档性，因为它使程序员的意图显式化。（我们将在第 14 章详细讨论这一主题。）

## 静态类

在第 9 章中，你使用了静态成员来允许类只有一个实例。每当尝试创建该类的实例时，你都可以测试变量的值以确保没有其他实例。这是因为声明为 `static` 的变量对类的所有实例都可用。

## 静态 Math 类

创建完全静态类允许我们封装一组相关的、不改变的数据和方法。对于这种类，数学类是理想的选择，因为有像 `pi` 这样的常量以及计算绝对值的方法。列表 11-3 显示了 `Math` 类可能的形式：

```php
final class Math{
  const PI = 3.14;
  static public function abs($num) {
    return abs($num);
  }
  static public function sqrt($num) {
    return sqrt($num);
  }
}
echo Math::PI;
echo '<br/>';
echo Math::abs(-4.15);
echo '<br/>';
echo Math::sqrt(9);
```

实例。让我们重修订 `MySQLConnect` 类，以突出静态方法的用处。（我在这里只列出主要的更改；如果你想查看所有更改，请下载代码）。

首先，原本设计用于跟踪实例数量的静态数据成员变为用于持有类实例引用的静态数据成员。

```php
private static $instance = NULL;
```

构造函数仍然会创建连接，但访问修饰符从 `public` 更改为 `private`，并且删除了对现有实例的测试。

```php
private function __construct($hostname, $username, $password){
    if(!$this->connection = mysql_connect($hostname, $username, $password))
        throw new mysqli(mysql_error(), mysqli_errno());
}
```

由于构造函数被声明为 `private`，你只能在类内部调用它。这看起来似乎是不可能实现的（你如何进入一个你无法创建的类呢？），但静态方法提供了这种手段，如列表 11-4 所示。

```php
static public function getInstance($hostname, $username, $password){
    //instance must be static in order to be referenced here
    if(self::$instance == NULL)
        self::$instance = new MySQLConnect($hostname, $username, $password);
    return self::$instance;
    } else {
        $msg = "Close the existing instance of the MySQL class.";
        throw new mysqli($msg, self::ONLY_ONE_INSTANCE_ALLOWED);
}
```

列表 11-4：返回实例的静态方法

为了在静态方法内部引用实例句柄，句柄本身必须是静态的。如果不存在实例，则会调用构造函数并将返回的对象复制到静态类变量 `$instance` 中。然后 `getInstance` 方法返回指向该静态数据成员的引用。

现在，不再通过调用构造函数直接创建 `MySQLConnect` 类的实例，而是调用 `getInstance` 方法来为你完成这一操作。

```php
$instance = MySQLConnect::getInstance('localhost', 'user', 'password');
```

之前提到过，静态方法只能引用静态数据成员。相反，静态方法被禁止引用普通数据成员。当你考虑到普通数据成员属于对象并在对象实例化时被创建时，这就会是合理的。根据定义，静态方法不需要对象，因此这些非静态数据成员并不。同样，正如你之前看到的，静态方法不能使用伪变量 `$this`；同样，`$this` 指向当前实例。

单例类也应该允许克隆。你将在第 13 章看到这是如何实现的。

## 何时实现？

这个修订后的 `MySQLConnect` 类与原始类具有相同的功能。除了创建实例的时机外，`MySQLConnect` 类的接口没有其他更改。然而，在静态类中存储一个实例的副本，允许你在尝试创建第二个实例时返回（现有实例）而不是抛出异常。这正是某些单例类实现所采用的，但并不总是所期望的行为。如果用户想要连接到不同的服务器怎么办？由于这个原因，在第 68 页的“创建其他连接”章节中，我们选择强制用户在创建新连接之前使用当前连接。

原始实现的编码风格可能更直接、更易于理解，但在某些情况下，拥有类实例的引用可能会证明是有用的。如果 `getInstance` 方法接收到到使用相同主机和相同用户名连接的请求，为什么不返回当前实例而不是抛出异常呢？

哪个版本更好？这取决于你的决定。

## 保持新鲜

发现一个新而有趣的网站的兴奋感是无可比拟的。但这种热情很快就会消灭，因为访问几次后，网站的内容完全没有变化。为网站添加新内容的主要方法是使用动态的、数据库驱动的页面。

## RSS 文件的结构

正如我们之前处理自己的代码时的那样，让我们逐步分析 RSS 代码，并在适当的地方添加注释。

XML 文件的第一个组件是版本声明。该声明显示了版本号，并且像下面的示例所示，它还可能包含关于字符编码的信息。

```
<?xml version="1.0" encoding="iso-8859-1"?>
```

在 XML 版本声明之后，下一行代码开始了文档的第一个元素。该元素的名称定义了 XML 文档的类型或根元素。出于这个原因，该元素被称为文档元素。惊讶的是，我们的文档类型是 RSS。这个起始元素定义了 RSS 版本号，并有一个匹配的闭合标签来结束文档，其方式与 `<html>` 和 `</html>` 打开和关闭网页非常相似。

```

```

一个格式正确的 RSS 文档需要单个的 `channel`（通道）元素。该元素将包含有关馈的元数据以及组成馈的实际数据。`channel` 元素有三个必需子元素：title（标题）、link（链接）和 description（描述）。在代码中，我们将提取通道标题来形成网页的页眉。

```xml
<channel>
  <title>About Classical Music</title>
  <link>http://classicalmusic.about.com/</link>
  <description>Get the latest headlines from the About.com Classical Music Guide Site.</description>
```

`language`、`pubDate` 和 `image` 子元素都包含关于通道的可选元数据。

```xml
<language>en-us</language>
<pubDate>Sun, 19 March 2006 21:25:29 -0500</pubDate>
<image>
  <title>About.com</title>
  <url>http://z.about.com/d/lg/rss.gif</url>
  <link>http://about.com/</link>
  <width>88</width>
  <height>31</height>
</image>
```

紧随其后的 `item`（项目）元素才是我们真正感兴趣的。`item` 的三个必需元素是 title、link 和 description。这是 RSS 馈中填充我们网页内容的部分。我们将使用 title 和 link 元素创建一个 HTML 锚点标签，并配合 description 元素。

```xml
<item>
  <title>And the Oscar goes to...</title>
  <link>http://classicalmusic.com/b/a/249503.htm</link>
  <description>Find out who won this year's Oscar for Best Music...</description>
</item>
```

这里只显示了一个 item，但可能会出现许多。在典型的 RSS 馈中，找到 20 个 item是很常见的。

```xml
</channel>
</rss>
```

`channel` 元素的结束之后是 `rss` 元素的结束。这些标签正确地嵌套在另一个内部，且每个标签都有匹配的结束标签，因此我们可以说这个 XML 文档是良好的（well-formed）。

### __get 和 __set

在本次讨论的背景下，记住我们在第 6 章中花了一些时间讨论访问器，或者说 set 和 get 方法。我主张实例变量应该是私有的，并且仅通过访问器方法获取。这样做违反了面向对象（OO）的数据隐藏原则（如果你愿意的话，可以称为封装），并使实例暴露在意外的改变之中。

PHP 5 引入了针对未定义变量魔 set 和 get 方法。让我们通过一个例子来看看这意味着什么。假设你有一个如下定义的类，没有任何数据成员或方法：

```php
class Person{
}
```


```php
class Person{
    protected $datamembers = array();
    public function __set($variable, $value) {
        // 也许检查传入的值
        $this->datamembers[$variable] = $value;
    }
    public function __get($variable) {
        return $this->datamembers[$variable];
    }
}
$p = new Person();
```

## 这值得吗？

引入魔 set get 方法是为了提供便利，但它们是否值得这些精力无疑值得怀疑。鼓励使用未定义的数据成员很容易在调试时导致困难。例如，如果你想更改实例的 `name` 数据成员的值，但拼写错了，PHP 会静静地创建一个实例变量。设置不存在的数据成员不会产生错误或警告，因此你的拼写错误将很难被发现。相反，尝试使用未的方法会产生致命错误。出于这个原因，将数据成员声明为私有（或保护），并确保它们都通过访问方法访问，可以消除意外创建数据成员的危险。使用定义的数据成员意味着更少的调试问题。

未定义的数据成员似乎违反了 OOP 的原则。尽管你可能会认为因为未定义的数据成员仅通过魔方法访问，所以封装得到了保留，但真正的代价是访问方法。允许未定义的数据成员破坏了 OOP 的另一个基本概念，即继承。很难想象派生类如何继承未定义的实例变量。

然而，人们可能会认为，这些方法让 PHP 更容易使用，便利性抵消了任何缺点。毕竟，PHP 原始且持续的动力是简化 Web 开发。在 PHP 5 中允许未定义的数据成员也许是一种必要的恶，这样做保持了与 PHP 4 的兼容性。虽然很容易批评魔 set 和 get 方法，但在第 16 章讨论 `PDODataRow` 类时，你会发现这些方法非常有用。

### __isset 和 __unset

PHP 5.1.0 引入了 `__isset` 和 `__unset` 魔方法。这些方法是由 PHP 内置函数 `isset` 和 `unset` 直接调用的。这些方法的出现源于针对未定义数据成员的魔 set 和 get 方法的存在。每当 `isset` 用于未定义的数据成员时，魔方法 `__isset` 就会被调用。

魔法方法 `__call` 对于未声明方法的作用，就相当于 `__get` 和 `__set` 对于未声明数据成员的作用。提供这个额外的方法是为了方便。起初，很难想象未声明的方法可能是什么样的，它可能包含什么。嗯，这里有一种该方法可以证明其用的方法。假设你想为第 9 和第 10 章中定义的 `MySQLResultSet` 类添加功能，以便如下所示检索当前状态：

```php
// $rs 是 MySQLResultSet 的实例
$rs->stat();
```

你可以仅为现有的 MySQL 函数 `mysql_stat` 创建一个包装方法，就像你在创建该类的其他方法时做的那样。例如，现有的 `InsertId` 方法封装了对 `mysql_insert_id` 的调用。你可以轻松地对 `mysql_stat` 这样做。然而，更灵活的选项是添加一个类似于下面代码的 `__call` 方法：

```php
public function __call($name, $args) {
    $name = "mysql_".$name;
    if(function_exists($name)) {
        return call_user_func_array($name, $args);
    }
}
```

当你对 `MySQLResultSet` 对象调用该方法时，方法名会被传递给 `__call` 方法，并在其前面加上 `mysql_`。随后，`mysql_stat` 方法由 `call_user_func_array` 函数调用。你不仅可以调用任何 MySQL 函数，一旦定义了 `__call`，你只需通过使用函数名（去掉开头的 `mysql_` 并提供任何所需的参数），就可以对 `MySQLResultSet` 类实例调用任何 MySQL 函数。这个魔法方法消除了为现有 MySQL 函数编写包装方法的需求，并允许它们被“继承”。如果你已经熟悉 MySQL 函数名，它也使得该类使用变得非常简单。

然而，这个魔法方法并不像初看时那样方便。像 `mysql_fetch_array` 这样需要传入结果的函数（即使该类本身就是结果集方法）会使整个对象的概念变得毫无意义——为什么对象在调用方法时需要传递它自己的一个副本呢？另一方面，整合像 `mysql_stat` 和 `mysql_errno` 这样不需要任何参数的函数，或者像 `mysql_escape_string` 这样需要原始数据类型作为参数的函数是非常容易且自然的。如果使用得当，这种便利方法似乎比 `__set` 和 `__get` 方法更有理由存在。

## __autoload

`__autoload` 函数是一种便利机制，允许你使用类而无需显式编写代码来包含它们。它与其他魔法方法有点不同，因为它没有包含在类定义中。它只是像其他过程函数一样包含在你的代码中。

通常，使用类时通过以下方式包含它们：

```php
require 'MySQLResultSet.php';
require 'MySQLConnect.php';
require 'Navigator.php';
require 'DirectoryItems.php';
require 'Document.php';
```

这五行代码可以被以下代码替换：

```php
function __autoload($class) {
  require $class '.php';
}
```

每当尝试使用未显式包含的类时，`__autoload` 函数就会被调用。类名将传递给这个魔法函数，通过创建持有该类定义的文件可以包含该类。当然，要像上面代码那样使用 `__autoload`，类定义文件必须位于当前目录或路径中。

当你的代码包含许多类时，使用 `__autoload` 特别方便。这不需要付出性能代价——在大多数情况下，它似乎忘记了使用未声明的数据成员，从而消除了对魔法 `set` 和 `get` 方法以及配套的 `__isset` 和 `__unset` 方法的需求。

## __sleep 和 __wakeup

这些魔法方法自 PHP 4 以来一直可用，并被序列化和反序列化调用。正如 `__toString` 方法控制对象的显示方式，`__sleep` 控制对象在序列化之前如何被存储。相反，`__wakeup` 由反序列化调用并恢复对象。

## 沃尔多在哪里？

在 PHP 5 中，将一个对象赋值给另一个对象并不是创建一个独立的对象，而是引用 $obj1 的另一种方式。对 $obj2 的任何更改都会影响 $obj1。在 PHP 5 中对对象使用赋值运算符等于 PHP 4 中的引用赋值。（你可能记得我们在第 4 章中对赋值运算符的使用。）

换句话说，PHP 5

```php
 //PHP 5
$obj2 = $obj1;
```

实现了与相同相同的结果

```php
 //PHP 4
$obj2 &= $obj1;
```

将对象传递给函数时，逻辑也一样。这并不意外，因为在将变量传递给函数时会发生隐式赋值。在 PHP 4 中，当对象传递给函数时，默认是按值传递，以与任何基本变量相同的方式创建一个副本。这种行为在 PHP 5 中发生了变化，因为按值传递会导致低效问题。按值传递会消耗内存；在大多数情况下，我们需要的只是引用。总结来说，当将一个对象赋值给另一个对象时，它是通过引用赋值的。然而，在某些情况下，你确实想创建一个对象的副本，而不仅仅是引用同一个对象。因此，需要引入 `clone` 操作符。

> 如果你正在将 PHP 4 代码迁移到运行 PHP 5 的服务器，你可以删除所有与按引用传递对象或按引用赋值相关的未未使用引用符号（&）。

## 使用反射类创建文档

在第 4 章中，我引入了一个名为 `DirectoryItems` 的简单类。你可能还记得它的作用，但可能忘记了具体的方法。对于用户自定义类，查找遗忘的方法通常意味着要翻阅类定义文件。这可能花费很长时间，特别是对于大型类来说。对于内部类，你可以去 http://php.net 查找你需要的信息。但是有超过 100 多个内部类和接口，它们的文档散落在整个 PHP 网站中。如果能有一个包含所有类的中央文档库，难道不会很有用吗？

找到文档是一个问题，文档的质量是另一个同样重要的问题。大多数开发者都知道准确注释代码的价值，但当你处于编码中间时，你代码的含义似乎总是是显而易见的，因此注释显得是多此一举。此外，缺乏内部文档总有一个终极借口——你想保持文件大小较小以缩短下载时间。

内部文档的情况通常是这样，但外部文档的情况也不过如此。在边写边写是没有意义的，因为事情总是在变化，但当你完成编码时，文档已经是你脑海中最遥远的事了。你准备好处理其他事情了。

本章为文档的随时可用性和质量这两个问题提供了解决方案。我们将创建一个基于 PHP 5 引入的一组新类——反射组（reflection group）的文档类。你将学习如何动态生成文档，以完全描述方法和数据成员，并为用户自定义类包含格式化正确的内部注释。

## 什么是反射类？

在第 10 章中，在实现 `Iterator` 接口之前，你必须理解它的方法。要创建一个自动为你编写文档的类，你需要熟悉反射类。这组类的创建目的明确是为了对其他类进行内省。这些类使得通过获取有关类的数据来检查类的属性成为可能；你甚至可以使用它们来检查反射类本身。

反射提供了关于类接口修饰符的信息——例如该类是否是 `final` 或 `static`。它还可以揭示类的所有方法、数据成员，以及应用于它们的所有修饰符。传递给方法的参数也可以被内省，并暴露变量名。通过反射，可以实现内置类或用户自定义类的自动化文档。事实证明，类的信息的中央库一直就在我们面前。PHP 可以通过反射类的“镜子”告诉我们一切。

## 反射类组

反射类组或应用程序编程接口（API）由许多不同的类和一个接口组成，如下所示：

```php
class Reflection
interface Reflector
class ReflectionException extends Exception
class ReflectionFunction implements Reflector
class ReflectionParameter implements Reflector
class ReflectionMethod extends ReflectionFunction
class ReflectionClass implements Reflector
class ReflectionObject extends ReflectionClass
class ReflectionProperty implements Reflector
class ReflectionExtension implements Reflector
```

我们不会关注反射 API 中的每一个类；一个通用的概述有助于理清思路。看着这个列表，你可能认为 `Reflection` 类是所有反射类的父类，但并不是所有反射类都有共同祖类。另一方面，`Reflector` 接口被 `Reflection` 和 `ReflectionException` 之外的所有类共享。在类层次结构方面，`ReflectionMethod` 继承 `Reflection`，`ReflectionObject` 继承 `ReflectionClass`，而 `ReflectionException` 继承 `Exception`。

我们关注的是对象，所以我们不会在 `Reflection` 方法上花费任何时间。`ReflectionObject` 共享 `ReflectionClass` 的所有方法；这些类之间的唯一区别是参数是一个实例而不是类名——使用实例，你可以在对类一无所知（甚至不知道名称）的情况下对其进行内省。`Reflection` 类继承自 `Exception`，这是我们已经检查过的类。

我们主要感兴趣的是 `Reflection`、`ReflectionClass`、`ReflectionMethod`、`ReflectionParameter` 和 `ReflectionProperty`。

## ReflectionClass 类

`export` 方法快速又简单；但如果你想以用户友好的格式获取更多信息呢？应该从 `ReflectionClass` 开始，我们将扩展它来创建一个文档类。

## ReflectionClass 的方法

`methods` 和 `getProperties` 方法在类文档中起着重要作用。调用 `methods` 返回一个 `ReflectionMethod` 对象数组。调用 `getProperties` 返回一个 `ReflectionProperty` 对象数组。这些方法以及返回的对象使得完全描述类的方法和数据成员成为可能。



幸运的是，`ReflectionMethod` 和 `ReflectionProperty` 都具有 `getDocComment` 方法，因此方法级和数据成员级的注释也可以包含在内。

注意：熟悉 PEAR（PHP 扩展与应用库）phpDocument 或 Java 工具 Javadoc 的朋友可能已经知道内部注释的正确格式。

## ReflectionMethod 和 ReflectionParameter

`ReflectionMethod` 对象包含了完全描述方法所需的所有信息。通过使用此对象，你可以记录方法的修饰符；你可以使用它的 `getParameters` 方法返回一个 `ReflectionParameter` 对象的数组，这对于描述方法的参数至关重要。

- `ReflectionParameter` 对象将为你提供参数数量、名称以及任何默认值。如果参数经过类型提示（type hinted），你甚至可以判断该参数是否为特定类型的对象——这是使用类型提示的另一个好理由。

在某方面，你可能会发现 `Reflection` 类有些不足。有时，知道方法返回什么是非常重要的；例如，在使用 `getMethods` 方法时，知道它返回的是一个 `ReflectionMethod` 对象的数组是必要的。由于你可以对参数进行类型提示并获取这些信息，如果对返回值也能这样做就就太好了。然而，由于 PHP 是一门弱类型语言，这种功能未被支持并不意外，因此请务必在适当的注释中注明返回类型。

注意：对返回值进行类型提示计划在 PHP 6 中实现，因此我们可能期待在反射类的未来版本中获得该功能的支持。

## ReflectionProperty

`ReflectionClass` 的 `getProperties` 方法与 `getMethods` 方法类似。它返回一个 `ReflectionProperty` 对象的数组，可以像 `ReflectionMethod` 对象一样对其进行查询。（确定数据成员是否存在默认值带来了一些挑战；稍后会详细介绍这一点。）

## 内置函数

我们已经查看了反射类的主要类和方法，但有一些 PHP 内置函数在编写类文档时也很有帮助。`Class/Object` 组中的大多数函数在 PHP 5 中已被有效使用，如果说显式地被废弃，因为现在有反射类可以完成更好的工作。然而，许多诸如 `get_declared_classes` 和 `is_object` 等函数仍然很有用。

## 你想要什么格式？

编写类文档的主要原因之一是让客户端程序员更容易使用。由于客户端程序员主要对类的公共方法感兴趣（他们想知道如何使用该类，而不是它是如何工作的），你应该按可见性（visibility）对方法和数据成员进行排序，优先考虑具有可见性的成员。

如果你曾经用过纯文本编辑器编写代码，就会知道语法高亮极大提高了可读性。因此，更改关键字外观的能力也是你希望整合到类中的一个理想特性。

你已经熟悉了反射类的功能，现在对可以使用哪些现成的功能以及你必须自定义哪些哪些内容已经有了大致的了解。你现在处于一个开始扩展 `ReflectionClass` 的良好位置。

## 描述 Documenter 类

至少你需要关于类的基本信息。`getFullDescription` 方法结合了现有的 `ReflectionClass` 方法，创建一个与实际类声明匹配的字符串。

```php
public function getFullDescription() {
    $description = "";
    if ($this->isFinal()) {
        $description = "final";
    }
    if ($this->isAbstract()) {
        $description = "abstract";
    }
    if ($this->isInterface()) {
        $description .= "interface";
    } else {
        $description .= "class";
    }
    $description .= $this->name . " "";
    if ($this->getParentClass()) {
        $name = $this->getParentClass()->getName();
        $description .= "extends $name";
    }
}
```

```php
$interfaces = $this->getInterfaces();
$number = count($interfaces);
if($number > 0){
  $counter = 0;
  $description .= "implements ";
  foreach($interfaces as $i) {
    $description .= $i->getName();
    $counter++;
    if($counter == $number){
      $description .= ", ";
    }
  }
  return $description;
}
```

此代码调用了许多自解释其功能的继承方法来构建类描述。稍微的复杂之处在于，由于一个类可以实现多个接口，`getInterfaces` 返回一个数组，因此需要一个 `foreach` 循环。当应用于 `SoapFault` 类时，`getFullDescription` 方法返回以下字符串：

class SoapFault extends Exception

SoapFault 被正确识别为类而非接口，它既不是 final 也不是 abstract，并且它对 Exception 的派生关系也被记录在案。这与你在导出该类时在列表 14-1 中看到的描述完全相同。

## 描述方法和数据成员

方法比数据成员更，接下来让我们处理如何适配反射类来记录方法。调用 `ReflectionClass` 的 `getMethods` 方法会创建一个 `ReflectionMethod` 对象的数组。每个方法的可见性可以通过 `ReflectionMethod` 类的 `isPublic` 或 `isPrivate` 方法来确定。

然而，你想按可见性显示方法。为了获取一个按可见性排序的 `ReflectionMethod` 对象数组，你需要遍历所有方法并为每个类型创建数组。让我们看看是如何实现的。

```php
private function createMethodArrays() {
  $methods = $this->getMethods();
  foreach($methods as $m) {
    $name = $m->getName();
    if($m->isPublic()) {
      $this->methods[$name] = $m;
    }
  }
}
```

```php
if($m->isProtected()) {
    $this->protectedmethods[$name] = $m;
}
if($m->isPrivate()) {
    $this->privatemethods[$name] = $m;
}
```

再次，代码非常简单。使用继承的 `ReflectionClass` 方法 `getMethods` 获取方法数组，并将每个 `ReflectionMethod` 对象存储在关联数组中，以方法名为键。每个数组都有对应的公共访问方法。例如，要检查类的公共方法，只需调用 `getPublicMethods`，它将返回由 `createMethodArrays` 填充的数组。

数据成员数组以相同的方式创建。你的类有 `createMemberArrays`，它使用继承自 `ReflectionClass` 的 `getProperties` 方法创建一个 `ReflectionProperty` 对象数组，从而创建公共、私有和保护的数据成员数组。这些随后可以通过访问方法检索。

## 构造函数

`createMemberArrays` 方法和创建方法数组的辅助方法都是私有的，并在 `Documenter` 类的构造函数被调用。

```php
public function __construct($name) {
    parent::__construct($name);
    $this->createDataMemberArrays();
    $this->createMethodArrays();
}
```

调用父类构造函数的位置值得注意。因为 `createMemberArrays` 和 `createMethodArrays` 都调用了父类的方法，因此先调用父类构造函数是至关重要的。否则会在尚未不存在的对象上调用方法。

## 方法和数据成员修饰符

了解类方法和数据成员的访问修饰符至关重要的。`ReflectionMethod` 和 `ReflectionParameter` 类都具有 `getModifiers` 方法，返回返回一个带有位字段的整数，用于标记不同的访问修饰符。你的 `Documenter` 类有自己的 `getModifiers` 方法，使用 `Reflection` 类的静态方法 `getModifierNames` 将这些标记转换为等效的字符串。





```php
public function getModifiers($r) {
    if($r instanceof ReflectionMethod ||
        $r instanceof ReflectionProperty){
        $arr = Reflection::getModifiersNames($r->getModifiers());
        $description = implode(", ", $arr);
    }else{
        $msg = "Must be ReflectionMethod or ReflectionProperty";
        throw new ReflectionException($msg);
    }
    return $description;
}
```

你希望确保只有 `ReflectionMethod` 和 `ReflectionProperty` 对象传递到此方法，因此你使用了 `instanceof` 运算符。该运算符在 PHP 5 中引入，取代了现在已废弃的 `is_a` 函数。该运算符允许你限制对支持 `getModifiers` 方法类的用法，并在传入错误的对象类型时抛出 `ReflectionException`。

当你将 `getModifiers` 的返回值传递给 Reflection 类的静态方法 `getModifiersNames` 时，将返回一个包含所有修饰符的字符串数组。连续调用 `isPublic`、`isStatic` 等方法可以实现相同的结果，但使用 `getModifierNames` 是获取方法和类成员字符串最简洁的方式。

## 没有共同祖先

你可能认为 `ReflectionMethod` 和 `ReflectionProperty` 对象拥有 `getModifiers` 方法是因为它们共享一个公共接口 `Reflection`，因此你可以将该方法的参数提示为此接口，以检查是否为该特定接口的实例。然而，你错了。`Reflection` 接口只有两个方法：`export` 和 `__toString`。从公共类继承方面来说，`ReflectionMethod` 继承自 `ReflectionFunction`，而 `ReflectionProperty` 没有父类。它们没有共同的父类。事实是，检查 `Reflection` 类的实例的结果与检查 `ReflectionFunction` 和 `ReflectionProperty` 本质上是相同的——但原因是错误的。这两个类恰好都有 `getModifiers` 方法纯属巧合。筛选正确类的另一种方法是内省变量以确定它是否具有 `getModifiers` 方法。

作为一个有趣的附带，当内省内置接口的方法时，修饰符始终是公共的（public）且抽象的（abstract）。在第 11 章中，你已经看到 PHP 禁止在定义用户定义接口的方法时使用 `abstract` 修饰符，尽管接口的方法实际上必须是抽象的。

## 方法文档

如图 14-1 所示，方法文档紧跟在类描述和注释之后。从客户端程序员的角度来看，公共方法显示类名和描述之后，随后是保护方法，最后是私有方法。由于 `MySQLException` 类没有保护方法，因此不显示。




所有可见性级别的方法都会传递给 `show_methods` 函数，以处理显示方法描述的细节。以下是该函数的原型：

```
function show_methods(Documenter $sd, $type, $arr)
```

该函数的参数之一是一个对象。在 PHP 4 中，你需要在变量前加上 `&`（取地址符）以确保该对象是通过引用传递的。正如在第 13 章第 116 页的 `__clone` 节中讨论的那样，在 PHP 5 中，所有对象都自动通过引用传递，因此没有需要这样做。此参数还进行了类型提示，不允许除 `Documenter` 对象之外的任何类型。

总结来说，此函数显示了方法参数的变量名、类型提示以及适用的默认值。对于描述每个方法的关键字使用了语法高亮——你可以从图 14-1 中快速看到，`Exception` 类的 `getMessage` 方法既是公共的（public）的也是受保护的（fine）。用户定义的方法会被标记为此类，任何内部注释也会被标记。

> 如果你运行的是 PHP 5.1 或更高版本，可以通过将函数原型更改为 `function show_methods(Documenter $sd, $type, array $arr)` 来为 `show_methods` 的数组添加提示。

## 数据成员

数据成员的处理方式与方法相同。可见性限制最少的优先显示。同样，关键字会被高亮。即使是分配给数据成员的默认值也可以被检索。令人惊讶的是，这是使用 `ReflectionClass` 的 `getDefaultProperties` 方法而不是使用 `ReflectionProperty` 类方法实现的。对于方法，所有的修饰符都会显示。常量的值通过 `ReflectionClass` 方法 `getConstants` 获取。

## 反射

反射类使得为内部类和用户定义类生成文档变得简单。文档可以直接从类文件中创建，因此对类的任何任何更改都会立即反映在文档中——这比单独维护代码和文档要容易得多。方法描述和关于类使用的提示不仅对于客户端程序员，而且对于类的创建者来说都是无价的，特别是当类的创建与其后续使用之间间隔了几个月时。只要你在编码期间稍微注意它们的格式，类文档就可以轻松地整合内部注释。

# SQLite 的用途与局限性

没有哪个数据库能满足人的所有需求。SQLite 支持任意数量的并发读取，但写操作会锁定整个数据库。版本 3 在这方面提供了一些改进，SQLite 最适用于数据库更新不频繁的应用程序，比如这里描述的这种。

当然，如果访问控制非常重要，SQLite 并不是合适的工具。它没有实现 `GRANT` 和 `REVOKE`，无法通过数据库强制执行用户限制。

然而，即使是相对简单的应用程序也可以利用 SQLite 的高级功能。通过本章讨论的应用程序，我们使用 SQLite 而非 MySQL 并没有牺牲任何东西。时间戳字段缺失通过使用触发器解决。UDF 弥补了 SQLite 缺少日期处理函数。事实上，整体而言，我们获得了更好的性能，因为没有数据库服务器的开销，而且通过触发器减少了维护工作。

使用 SQLite 不仅通过视图、触发器和 UDF 以及扩展 OO（OO）接口简化了我们的代码，还通过其多样的数据库查询方式使得代码更加简洁。在这些或类似的情况下，SQLite 绝对是一个优越的选择。

## 使用 PDO

数据库对任何动态网站都至关重要。这就是为什么我们在书中对它们做了很多介绍（你们中有些人可能在想说太多了）。PHP 数据对象（PDO）是不容忽视的，因为它们在 PHP 5.1 及更高版本中自带，并且它们是“许多 PHP 开发团队希望看到的数据库工作推荐 API 的东西”。¹

PDO 是一个数据访问抽象层，旨在实现对任何数据库的统一访问。这是查看 PDO 的一个很好的理由，但我们特别感兴趣的是 PDO 接口完全是面向对象（OO）的。它大量利用了 PHP 5 的面向对象改进。事实上，它无法在较低版本的 PHP 上运行。

PHP 支持的所有主要数据库都提供了驱动程序——Oracle、Microsoft SQL Server、PostgreSQL、SQLite 以及直到版本 5 的所有 MySQL 版本。因此，如果你使用多种不同的数据库，PDO 特别值得研究。

# 优点与缺点

由于 PDO 连接可以配置为抛出异常，因此我们不需要派生类 `SQLiteDatabasePlus` 的查询方法。然而，我们添加的实用方法是另一回事。使用这些方法的唯一方法是将它们还原为函数。它们可以很容易地转换，其采用的元数据查询与之前一样。唯一的真实区别是，作为函数，它们使用起来没有那么方便。我在这里不再重复它们，但可以在本章下载的 `dbfunctions.file` 中找到它们。

## 转义输入

我们派生类的 `cleanData` 工具方法整合了 `sqlite_escape_string` 函数，在插入数据库之前对输入进行转义。相应的 PDO 方法是 `quote`。请注意，该方法不仅会转义引号，还将把引用的项包含在引号内。如果你需要在插入数据之前对其进行处理，则只应在插入之前调用 `quote`。出于可移植性考虑，PHP 官网建议使用预处理（prepare）而不是 `quote`。我们将在第 161 页的“PDO 的附加功能”章节中讨论语句时充分调查这种方法。

## 查询方法

SQLite 的魅力之一是它多种查询方法。如果你需要快速回顾，请查看第 148 页的“查询方法”章节。在本节中，我们将比较 SQLite 的查询方法与使用 PDO 提供的可用方法。

SQLite 和 PDO 对象模型之间的差异使得直接比较变得有些别扭。主要是，查询 PDO 连接返回一个语句对象（statement object），这个语句一旦执行，实际上就变成了一个结果。正如前面提到的，我们将在第 161 页的“PDO 的附加功能”章节中介绍语句，但目前我们可以将其等同于结果集。

SQLite 的五种查询方法是 `singlequery`、`execquery`、`arrayquery` 和 `unbufferedquery`。我们将逐一讨论每个 SQLite 方法。

`singlequery` 方法以数组形式返回单列，跳过了创建结果集的需要。为了模拟它，我们使用一个 PDO 查询返回一个语句，然后对该语句调用 `fetchColumn`。`fetchColumn` 方法可以返回当前行中的任何列。

SQLite 结果集的 `execquery` 方法可以执行多个由逗号分隔的行。PDO 可以很容易地管理这种行为——事实上，这正是语句所擅长的。

正如你预期的那样，以 `arrayquery` 的方式返回数组也可以通过 PDO 对语句调用 `fetchAll` 方法轻松处理。

SQLite 剩余的查询方法 `query` 和 `unbufferedquery` 分别返回 `SQLiteResult` 和 `SQLiteResBuffer` 对象。PDO 语句类似于非缓冲结果集（unbuffered result sets）而不是缓冲结果集，非缓冲行为可以很容易地实现。SQLite 应用在我们需要知道是否返回了记录，或者需要特定记录数量的情况下，使用了缓冲结果集。若要使用 PDO 进行缓冲，可以使用语句的 `fetchAll` 方法返回数组。通过对返回的数组使用 `count` 函数可以获取记录数。或者，在查询返回的语句上调用函数 `empty` 将判断是否至少有一个记录。

总的来说，在查询数据库时，看起来使用 PDO 增加了一些效率上的处理。在 SQLite 中是单步完成的过程，在 PDO 中变成了两步过程。使用两个方法而不是一个方法可能会使代码变得复杂。然而，正如我们很快看到的，PDO 方法具有一些重要的优势，在某些情况下，这个两步过程可以被简化。

## PDO 的附加功能

仅仅转换一个应用程序显然不能说明 PDO 的全部情况，所以让我们来看看 PDO 的其他一些功能。有三个类：`PDO`（数据库或连接类）、`PDOStatement` 和 `PDORow`。到目前为止，最有趣且最陌生的类是语句类，我们将重点放在这里。当我们使用语句类的 `fetchObject` 方法时，我们会简要讨论 `PDORow`。

## PDO 类

到目前为止，我们创建了自己的连接类，并使用了与 PDO 有许多相似之处的 `SQLiteDatabase` 类。有了经验，我不需要对 PDO 类说太多。

我已经提到了 PDO 类的 `quote`、`setAttribute` 和 `query` 方法。对于像 SQLite 这样支持事务的数据库，该类还有开始（begin）、提交（commit）或回滚（rollback）事务的方法。

## 获取对象

对于面向对象的程序员来说，以对象形式检索行是重要的。PDO 有多种实现这种方法。实现这种功能的一种简单方法是通过以下方式创建 `PDORow` 类的实例：

```php
$stmt = $pdo->query("SELECT * FROM tblresources", PDO::FETCH_LAZY);
$pdorow = $stmt->fetch();
```

还有一个 `fetchObject` 方法，可以用于创建特定类的实例。假设我们定义了一个类 `RowInfo`，通过这种方式创建该类的实例：

```php
$row = $stmt->fetchObject('RowInfo');
```

这可能是创建对象最简单的方法。你可以与现有的类一起，或者如果不指定类，它将创建 `stdClass` 的实例，这是一个通用对象类。

## 评估

我们已经接触了 PDO 的许多功能。我们在应用程序中使用了一些功能，但并非全部。虽然这只是是对 PDO 的一个定性概述，但我们确实有足够的信息来对这个数据访问抽象层的用处做出判断。

我们的应用程序的行为与没有 PDO 的时候完全一致。我们没有牺牲任何功能，而且某些东西实现起来变得简单得多——例如捕获异常。我们所有的查询、触发器和视图工作方式完全相同。唯一的一个微小不便是转换派生类的实用方法，但我们能够以过程化的方式实现它们，而不会丢失功能。PDO 的对象模型可能稍微困难一点，但随之的是，我们获得了在需要时使用预处理语句的能力。PDO 与 SQLite 配合得很好。

但如果我们决定使用 MySQL 后端呢？我们需要做多少更改呢？更改驱动程序是最明显的更改，这会移除针对 SQLite 特有的函数 `sqlite_create`。正如第 15 节所示，这将由 MySQL 函数所取代。同样，任何 MySQL 未使用的其他运算符或函数也必须进行更改。

另一个选项是尽可能使用标准 SQL。日期处理函数可以被忽略，该任务可以在 PHP 内部完成。这是每个开发者都必须自己做的选择，但我预计大多数人不会很快放弃关于特定 SQL 方言的来之知识。

## 它是圣杯吗？

一个合理的担忧可能是针对 SQLite 特有方法 `sqlite_create` 的引入，而且这不仅仅是 PDO 提供的特定数据库的功能。提供特定数据库的功能难道不正是我们在开始时所克制没有做的——扩展 PDO 类吗？

简短的回答是，毫无疑问，但完美数据库抽象层的整个概念是一个圣杯——在这里瞥见，但从未被掌握。提供某些特定数据库的功能是一种明智的折协，也是 PDO 的一种动力。与 PHP 一样，实用性和概念的纯洁至关重要。需要注意的是，每个开发者都可以根据情况通过是否包含特定数据库的方法和特定 SQL 来对可接受的数据库抽象级别做出自己的决定。然而，在某方面完全没有可选择：如果你选择使用 PDO，就必须采用面向对象的方法。

> 常量 `PDO::MYSQL_ATTR_USE_BUFFERED_QUERY` 可用于为 MySQL 数据库创建缓冲结果集。使用 `fetchAll` 是更抽象或与数据库无关的方法。

## php.ini 设置

php.ini 文件控制 PHP 的配置设置，在 Windows 系统上通常位于 c:\windows 目录，在 Linux 系统上位于 /etc 目录。安装 PHP 5 时，最好使用带有默认设置的示例 php.ini 文件。本节涉及影响 OOP 的更改。（要查看所有更改的概述，请参见 http://php.net/install/）。

只有一个与 PHP 5 中对象模型更改直接相关的新配置设置。具体来说，显示默认设置：

```
zend__compatibility_mode = Off
```

如果你将此设置改为 On，对象将以 PHP 4 的方式按值复制。（在第 116 页的“clone”部分获取更多关于如何复制对象的详情。）提供此选项是为了方便从 PHP 4 迁移到 PHP 5。它应该仅为此目的使用，因为在未来的任何 PHP 版本中可能都不支持。

另一个对 PHP 5 对象模型更改有某些影响的设置是

```
allow_call_time_pass_reference = Off
```

此设置控制在引用传递时是否发出警告。当设置关闭时，如下方式调用函数将发出警告：

```
some_function(&some_variable);
```

按引用传递变量的方法是在函数定义中将参数声明为引用，例如：

```
function some_function ( &$some_variable ) {
```

如果你这样做，就不需要在调用时使用引用符号（你会记得 PHP 5 对象会自动按引用传递，在函数定义中也不需要。）

## E_STRICT

引入了一个新的错误级别 E_STRICT，它在 OOP 的背景下特别有用。如果你将错误报告设置为此值，当使用弃用函数或编码风格时将发出警告。Error_ALL 不包含 E_STRICT，因此在 php.ini 文件中按如下方式显式包含此错误：

```
error_reporting = E_ALL|E_STRICT
```

当设置为 E_STRICT 时，其他操作也会引发警告：

- 使用 is_a 代替 instanceof。
- 静态地调用非静态函数（此错误即将变为 E_FATAL）。然而，针对实例变量调用静态方法不会引发警告。
- 使用 var 代替 public、private 或 protected（在 5.1.3 之前的版本）。
- 在派生类中重写方法时更改参数数量或类型提示。

确保你的代码遵循严格标准有助于确保其具有向前兼容性，特别是在静态调用动态方法方面。

## 不要重复转义

最后一个对 OOP 有影响的设置。值得注意的是，魔术引号的默认设置为

```
magic_quotes_gpc = Off
```

正如你所看到的，PDO 类的 prepare 方法会自动转义数据库查询。因此，如果开启了魔术引号，可能会因为双转义而损坏数据。更改此设置时要小心。

## M
魔方法 (magic method) 以双下划线 `__sleep` 开头的方法，通常被间接调用。`__wakeup` 是 PHP 4 中的魔方法。PHP 5 了一些新的魔方法，最重要的是 `__construct` 和 `__clone` 方法。

元数据 (metadata) 描述其他数据；例如关于数据库结构的信息

方法 (method) 在类作用范围内定义的函数

多用途互联网邮件扩展 (MIME) 标准的互联网电子邮件格式，但更广泛地说，是一种内容类型规范，例如 "image/jpeg"

## N
键值对 (name/value pair) 传递给 Web 页面的查询字符串格式；任何查询字符串由一个或多个键值对组成。通过全局数组 `$_POST` 或 `$_GET` 访问，名称作为数组键。

重载 (overloaded) 方法的一种特征；描述在提供不同参数时表现出不同行为的能力。在 PHP 中，此术语通常用于 `__call`、`__set` 和 `__get` 方法，意味着一个方法可以处理多个不同的方法或属性。（由于 PHP 是弱类型语言，你无法拥有在某些其他面向对象语言中理解的那种重载方法——即方法名相同但签名不同。）

重写 (override) 在子类中重新定义父类方法的行为

## P
父类 (parent class) 参见基类 (base class)。

PHP 数据对象 (PDO) 一组提供数据访问抽象层的类的集合，默认包含在 PHP 5.1 及更高版本中；为 PHP 常用的数据库提供了驱动程序。

PHP 扩展与应用程序库 (PEAR) 一个开源代码库，组织成包，可以使用 PEAR 安装器轻松安装。

多态 (polymorphism) 严格来说，将子对象复制到父类型的变量中，并仍然针对父对象调用子类方法的能力；在应用于 PHP 时用得较为松散。

私有 (private) 用于修改类的方法或数据成员的关键字；私有元素只能从类内部访问，或通过访问器方法间接访问，且不能被继承。

过程化的 (procedural) 一种大量使用过程或函数调用的计算机语言；例如，C 语言是过程化语言，而 PHP 可以按过程化或面向对象的方式使用。

属性 (property) 与实例变量或数据成员同义。

保护的 (protected) 可以应用于方法或数据成员的关键字。与类的私有元素一样，保护元素不能在类外访问；与私有元素不同，保护元素会被派生类继承。

原型 (prototype) 在定义函数之前对函数进行声明（某些语言需要，但 PHP 不需要）；可以应用于方法的声明，特别是关于接口的。

公有 (public) 用于修改类的方法或数据成员的关键字；类的公共方法（有时称为类的接口）可以在类的实例上被调用，并被派生类继承。

## Q
查询字符串 (query string) 作为 URL 的一部分传递给 Web 页面的一个或多个键值对

## R
RSS (实时简单信息订阅或富内容摘要) 通常被称为新闻馈送；符合特定的 XML 格式。

## S
作用域 (scope) 变量可以被访问的上下文。在方法内部定义的变量只能在该方法内引用，而实例变量的作用域是整个类。

作用域解析符 (scope resolution operator) 运算符 `::`，在引用常量或静态方法时与类名配合使用。

浅拷贝 (shallow copy) 一个与原始对象独立的对象拷贝。在拷贝聚合对象时，必须特别小心避免创建浅拷贝。

签名 (signature) 函数或方法的唯一属性，由函数或方法名以及参数的数量和数据类型组成，在应用于 PHP 时用得较为松散。在强类型语言中，方法可以同名，只要参数的数量或类型不同，它们具有唯一的签名。

标准通用标记语言 (SGML) 一种表示文件的国际标准；HTML 和 XML 均源自 SGML。

标准 PHP 库 (SPL) PHP 内置的类集合。

静态 (static) 应用于类方法或变量的修饰符，允许无需创建实例即可访问该元素；静态变量或方法是类的所有实例共。

驼峰命名法 (studly caps) 一种命名约定，复合名称附加单词的首字母大写；有时称为驼峰命名 (CamelCase)。类名使用大驼峰命名（如 `DirectoryItem`），方法使用小驼峰命名（如 `getName`）。

## T
类型提示 (type hinting) 通过在函数或方法定义中的参数名前加上对象类型，来限制传递给函数或方法的对象类型；从 PHP 5.1 开始，数组也可以进行类型。

## W
弱类型 (weakly-typed) 用于描述像 PHP 这样的语言，在声明变量时不需要识别数据类型。

Web 服务定义语言 (WSDL) 一种描述 Web服务的 XML 格式。

万维网联盟 (W3C) 负责开发万维网标准的组织。

封装方法 (wrapper method) 一个简单封装现有函数调用的方法。

## X
XHTML (可扩展超标记语言) HTML 的一种符合 XML 的形式。

XML (可扩展标记语言) 一种类似于 HTML 的标记语言，源自 SGML；符合 XML 的文档必须比 HTML 文档更严格的要求。

## Z
Zend 引擎 (Zend engine) PHP 底层的脚本引擎；它为 PHP 5 被完全重写，以支持改进的面向对象能力。
