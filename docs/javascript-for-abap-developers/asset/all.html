1    Introduction to JavaScript and its Basic Principles

JavaScript started life as a programming language that allowed you to take static webpages and add complex logic to dynamically react to user input or application programming interface (API) changes. Since then, it has developed into an all-purpose programming language that can be used to build almost anything with its vast ecosystem of libraries and frameworks. Undoubtably, one of the frameworks you might have heard of is part of the SAP product range, SAPUI5, or OpenUI5, which is the open-source version of SAPUI5.

JavaScript runs in all modern web browsers: Chrome, Firefox, Safari, Edge, and so on. With the introduction of runtimes such as Node.js, JavaScript also runs on servers, much like ABAP runs on the ABAP stack. This means JavaScript is no longer just a frontend language anymore but can perform backend server logic as well, effectively letting you build and run full stack applications using JavaScript code alone.

JavaScript at its core is a single-threaded, synchronous programming language, which means each piece of code is executed in the order it was written. This can become a limitation, as your functions cannot execute until the previous function has completed its action. In Section 9, we will learn more about how to overcome this limitation using a concept called asynchronous JavaScript, which allows a function to run in the background without holding up the functions directly after.

Coming from ABAP, one of the main differences to get used to with JavaScript is its flexibility and dynamic (loose) typing system, which we’ll discuss further in Section 2. Many of the errors in your JavaScript will only become apparent at runtime. This contrasts with ABAP (which is a compiled language), which has the benefit of catching most of these errors at compile time. So, it is crucial you implement proper error handling wherever possible.

One of the biggest benefits of JavaScript is that you can write and execute your code almost anywhere. You do not need a connection to an SAP instance as you do with ABAP to run your code. That is why, throughout this E-Bite, we encourage you to try absolutely everything you read. The best and quickest way to learn JavaScript is by constantly trying out the new concepts you read about.

In this section, we’ll get started with the important concepts to develop a contextual understanding of JavaScript. We’ll discuss compatibility, runtimes, preparation steps, and how to execute your first piece of JavaScript code in the browser and with Node.js. We’ll end with a look at how comments function with JavaScript.

1.1    ECMAScript and Browser Compatibility

ECMAScript is the formal standard of the JavaScript programming language and has been in use since 1997. ECMAScript (ES) highlights the different releases of JavaScript and what features are included with each version. This is important because different browsers support these releases in certain browser versions. Some browsers don’t support certain versions at all, as is the case with Internet Explorer not supporting ES6 (ECMAScript 2015). Compare this to ABAP releases, where certain features are only available on later versions.

Note

You can see the full version history of ECMAScript at https://en.wikipedia.org/wiki/ECMAScript.

ES6 is one of the more well-known examples where new keywords like let and const were introduced (which we will cover in detail in Section 2). These are considered modern JavaScript keywords in comparison to the older var statement used to define variables. This E-Bite is all about modern JavaScript, so it is important to understand ECMAScript and to stay up to date on new features or standards as they are released.

1.2    Runtimes and Engines

The JavaScript code you write can be executed inside a web browser, on your local machine, or even on a server. Web browsers have their own runtime environments that let your JavaScript interact with the webpage’s Document Object Model (DOM), the browser itself (like using local or session storage), or external APIs (where you make a call to a server).

For a browser to use your JavaScript code, it must run its own JavaScript engine so it can parse your code and turn it into executable commands that your machine understands. For example, Chrome has the V8 JavaScript engine, Firefox has SpiderMonkey, and Microsoft Edge has Chakra.

Runtimes and engines are an important concept because your JavaScript code will need to run in more than one environment, and not all features are supported equally in every browser or browser version (see Section 1.1).

We’ll discuss how to run JavaScript with Node.js in Section 1.5.

<script src="app.js"></script>

</html>

2    Variables and Data Types

As with ABAP, JavaScript variables are there to store values that can be used throughout your program. As mentioned in section Section 1, vanilla (standard) JavaScript is a loosely typed programming language, while ABAP in comparison is strongly typed. This means that you can define a variable in JavaScript with just a value and no type declaration, like an inline declaration in ABAP. However, in JavaScript, you can also declare a variable with no value and its type would remain undefined until you assigned a value to it. You can even reassign variables, so if a variable is of type number, you can change its type to string just by reassigning a new string type value to it.

This flexibility is great because it allows you to quickly build something, make changes, and execute ideas without adhering to the strict rules of something like the ABAP compiler. However, you must approach your variables with caution as you use them throughout your code; a function might rely on a variable being of a certain type, and since it’s easy for that variable type to change, that function is more likely to break for no apparent reason.

In this section, we’ll run through how to declare variables using old versus modern syntax, as well as what data types you can use. We’ll also look at accessing those variables in the context of global and local scope.

2.1    Variables

In ABAP, you use the DATA statement to define a variable, including its type and possibly a value as well, as follows:

DATA: lv_car TYPE string VALUE "Mercedes".

In JavaScript, you declare and assign values to your variables using the assignment operator (the = sign). You also have comparison operators that look remarkably similar; for example, ==, which means “equal to.” We will look at comparison operators in more detail in Section 3. Using the = sign in your variable declarations will look like Listing 2.1.

var a = 10;        // Assign a numeric value to a
var b = 12;        // Assign a numeric value to b
var c = a + b;    // Assign the sum of a and b to c
console.log(a)
console.log(b)
console.log(c)

var applePrice = 10;            // Assign a numeric value to a

  • Identifiers are case sensitive. A is different than a.

  • Identifiers must not use reserved JavaScript keywords like var or function.

  • Identifiers can contain numbers, letters, dollar signs, and underscores.

  • Although not really a rule, you can decide if you want to use camel case or not.

2.2    Data Types

In JavaScript, you have six data types known as “primitives.” A data type in JavaScript is considered primitive if it is not an object and has no methods that can be used to change it (the data types themselves are immutable).

This contrasts with JavaScript structural types, like arrays and objects, which are mutable and can be changed using object and array methods built into JavaScript itself (which we’ll discuss in more detail in Section 5). Listing 2.6 shows a list of some of the data types (both primitive and structural) and how you could declare them.

var car // undefined (primitive type)
var weightKg = 10; // Number (primitive type
var dogsName = "Spot"; // String (primitive type)
var isTaskComplete = false; // Boolean (primitive type)
var numberArray = [1,2,3,4,5] // Object (structural type)
var object = {firstName:"John", 
lastName:"Smith"}; // Object (structural type)

Listing 2.6     JavaScript Types

You can declare empty variables, where the value and type are both undefined, as follows:

var car; 
console.log(car); // undefined
console.log(typeof car); // undefined

You can also declare a blank variable where the value is blank but the type is string, as follows:

var car = ""; 
console.log(car); // blank
console.log(typeof car); // string

To make things more complex, you can take a variable like car and change its type in the same scope. This is why JavaScript is said to have dynamic types, and why you need to pay special attention to your variables. For example, Listing 2.7 shows how we start with a car variable with type undefined and assign a string BMW, which changes the variable type to string. We then change the type twice more, from string to boolean and finally to number, just to assign a new value.

var car;
console.log(typeof car); // undefined
car = "BMW";
console.log(typeof car); // string
car = true;
console.log(typeof car); // boolean
car = 24;
console.log(typeof car); // number

Listing 2.7     Dynamic Types

Another important concept regarding data types in JavaScript is how JavaScript evaluates expression from left to right, and the results can be different depending on what combination you use. This is in stark contrast to ABAP, where variables must be typed first and you will get a type error if you try to add a string to a number. In the following example, the number 42 will be treated as a string because the first part of the expression is the string "apple":

var fruit = "apple" + 42;
console.log(fruit); // apple42

If you then try adding two numbers together first, followed by the addition of a string as in the following example, you will find the numbers sum up correctly but "apple" is tagged on the end. So, it ran the calculation first and then continued to the addition of the string.

var fruit = 42 + 8 + "apple";
console.log(fruit); // 50apple

As you have seen, JavaScript has a built-in operator called typeof, which you can use to check the data type of your variable. Listing 2.8 shows how variable fruit1 is type string when evaluating the expression from left to right, but following that same logic, variable fruit2 is also type string even though we started out with the calculation on the left and added a string.

var fruit1 = "apple" + 42;
console.log(typeof fruit1); // string
var fruit2 = 42 + 8 + "apple";
console.log(typeof fruit2); // string

2.3    Scope of Global and Local Variables

In ABAP, we are familiar with the concept of global and local variables. In a simple report with a subroutine (FORM…ENDFORM), we can declare a global variable outside the subroutine, which both the program and subroutine can access. Consequently, we can also declare a local variable within the subroutine scope (inside the FORM…ENDFORM) where it is only accessible to the subroutine and not the rest of the program. In JavaScript, you also have global and local variables, but your program scope is also split into global scope and local scope. Variables declared in the global scope can be accessed from anywhere, but variables declared inside a function (local scope) can only be accessed inside their respective scopes (not from the global scope). Local scope can further be divided into function scope and block scope. We’ll walk through each in the following sections.

Global Scope

In Listing 2.9, we declare the variable car in the global scope and log this variable to the console within a function’s local scope. The function can access the car variable and log it to the console because the variable has been declared in the global scope.

var car = "BMW"; // Declared in the Global scope
function showCar() {
  console.log(car); // car is accessible in this function
}
showCar(); // BMW

Listing 2.9     Global Scope

Local Scope: Function Scope

Function scope is the scope inside the curly brackets {…} of a function (see Section 4); variables declared here are only accessible within the function itself. Following the same example in Listing 2.10, we now declare our variable within the function scope. If we try to log the car variable outside the function, you will get a ReferenceError.

function showCar() {
  var car = "BMW"; // variable declared inside the function scope
  console.log(car); // car will be logged to the console
}
showCar(); // BMW
console.log(car); // ReferenceError: car2 is not defined

Listing 2.10     Function Scope

Local Scope: Block Scope

Block scope is the scope inside the {…} of JavaScript statements like switch, if, for loops, and while loops. The variables declared within the scope of these statements are also only accessible inside their respective statements’ block scope. However, this rule only applies to variables declared using modern JavaScript syntax, i.e., let and const. Watch how, in Listing 2.11, a ReferenceError is triggered when trying to log car2 to the console.

function test() {
  if (true) {
    var car1 = "BMW"; // old syntax - in function scope
    let car2 = "Audi"; // modern syntax - in block scope
  }
  console.log(car1); // BMW
  console.log(car2); // ReferenceError: car2 is not defined
}
test();

Listing 2.11     Block Scope inside the Function Scope

The reason why you cannot log car2 is because it uses the modern syntax let and is locked into the block scope of the if statement, where even the function containing the if statement cannot access it. Since car1 was declared using the older syntax, var can be accessed by the function, as it does not adhere to the if statement’s block scope.

2.4    Old Syntax versus Modern Syntax

Before ES6 (ECMAScript 2015), we only had the var keyword to declare variables in JavaScript. From ES6 onward, we have the let and const keywords, giving us more flexibility over var. These two new keywords are almost identical in nature, except let allows you to reassign a new value (like var), whereas const does not. They also allow us to declare variables that use block scope (see Section 2.3), whereas before ES6, we only had function scope and global scope.

We’ll walk through each keyword in the following sections.

var

Variables using the var keyword can be changed as well as redeclared. This was one of the reasons let and const were introduced, giving us more control over our variables and making code less error prone, as we can now decide whether or not to restrict a variable. Listing 2.12 shows how to both change and redeclare a variable using var. Here, the variable firstName is declared with value John, then its value is changed to Johnny, and finally redeclared as Fred.

var firstName = "John";
console.log(firstName); // John
firstName = "Johnny"; // Changing a variable
console.log(firstName); // Johnny
var firstName = "Fred"; // Delared a 2nd time
console.log(firstName); // Fred

Listing 2.12     var Keyword

The output is as follows:

John
Johnny
Fred

let

Variables using the modern let keyword can be updated (reassigned) but not redeclared in the same scope, making it the popular successor to the var keyword. In Listing 2.13, notice we can change the variable value when declared using let, changing John to Johnny.

4.3    Global Scope and Closures

We looked at the function scope in Section 2.3, which explained that we can access variables declared in the global scope (i.e., outside of the function) but variables declared inside a function are considered “private” to that function and are not accessible to the function caller.

However, the downside is global variables in JavaScript are accessible to any other function in the global scope, which can wreak havoc in your application. What we want is a way to create a global variable but lock down its scope so that only a certain function can access it. This is the same concept in ABAP classes with their PRIVATE SECTION declaration. Only the methods in that class can access those private variables, but those variables are declared outside the class methods themselves.

In JavaScript, this problem is solved using a concept called closures, which is essentially a function that wraps another function in a function scope so that when you call the parent function (which is like a wrapper), you create a parent function scope. Inside that parent function scope, you have another function that can access any variables within the parent wrapper.

Let’s walk through a simple example where we create a flexible calculator, as shown in Listing 4.5. First, you define the flexiSumCalculator parent function as the scope (wrapper), with a parameter param1 that is assigned to the private variable valueToAdd. Inside this wrapper, you define a return function calculator that returns the sum of the valueToAdd variable and the child function param2 parameter.

So, you create a version of the calculator, e.g., flexiSumCalculator5, which will add 5 to any value you pass in. You do this by creating a const function variable of the flexiSumCalculator parent function. This function variable takes and stores param1 as a global private variable for that version of the calculator, like an instance of a class in ABAP. You can then invoke that new flexiSumCalculator5() function and pass any value you want (as param2), and it will return param2 plus 5.

// Parent function "scope" wrapper
const flexiSumCalculator = (param1) => {
  let valueToAdd = param1; // our new "private" variable
  // Function that returns the calculation
  return (caluclator = (param2) => {
    return (param2 += valueToAdd);
  });
};
const flexiSumCalculator5 = flexiSumCalculator(5); /* 
Invoking the new version with param2 */
console.log(flexiSumCalculator5(1)); // 6
console.log(flexiSumCalculator5(2)); // 7
console.log(flexiSumCalculator5(3)); // 8

Listing 4.5     JavaScript Closures

So, when you create a version or instance of the calculator, you use param1 to determine what the private variable will be. When you call this new function variable, you pass in a parameter, which is param2. The function variable can now be reused safely so when you run the above code, you get 6, 7, and 8 logged to the console using the same function variable flexiSumCalculator5().

If the output is negative, it means b is greater than a and needs to stay in its current position, as the order is ascending. If the output is positive, it means b is smaller than a and therefore b needs to shift in front of a. This logic continues through the whole array until the correct ascending order is set. If you want the numbers to be in descending order, switch the logic around and instead run b – a.

9    Asynchronous JavaScript

Up until this point, you have used JavaScript in a synchronous way without really knowing it. JavaScript is by nature a synchronous language, which means functions are executed in the order they were written, or more simply put, functions can only be executed one at a time. That point highlights one of the biggest downsides of standard JavaScript, i.e., each function must finish executing before the next one can start, causing what is known as blocking. Blocking can render your webpage slow and unresponsive. This is similar to when an ABAP program specifies COMMIT WORK AND WAIT, where the program has to wait for the result of that commit before continuing on.

This is where asynchronous JavaScript comes in. Asynchronous JavaScript is a way for you to get around the linear flow of standard JavaScript and add some flexibility to your code, so you can either wait for a function to finish executing or let it execute in the background and finish in its own time. This is similar to an ABAP program called COMMIT WORK where the program doesn’t wait around for the result of the commit. Note that this is an advanced JavaScript topic, but one worth being introduced to from the beginning. Asynchronous JavaScript is illustrated in Listing 9.1 with the JavaScript setTimeout() function, which pauses the function execution for a few seconds. Notice how the function callExternalServer() does not hold up the doSomethingElse() function (even though it is executed before) and lets the rest of the program continue until it completes.

const doSomething = () => {
  console.log("Do something");
};
const callExternalServer = () => {
  setTimeout(() => {
    console.log("Call to external server complete");
  }, 3000);
};
const doSomethingElse = () => {
  console.log("Do something else");
};
doSomething();
callExternalServer();
doSomethingElse();

Listing 9.1     setTimeout() Function

In this section, we’ll look at the older JavaScript callbacks, the JavaScript promise, and finally the newer async/await syntax, which gives much more granular control over when our JavaScript logic executes.

9.1    Callbacks in JavaScript

Callbacks are one of the older coding strategies in JavaScript but you will see them often. They involve passing a function as a parameter to another function. The idea is that you create your first function that runs until completion and when it does, it calls another function, known as the callback. Think of it as sending someone a message and asking them to do something and “call you back” when they are done.

This allows for more granular control over when functions are executed and allows you to handle scenarios where one function relies on another to complete before it can start. A great way to illustrate this is with a calculator. In Listing 9.2, we create a calculator we can pass some numbers into and when the calculation is done, we call another function that logs that result to the console.

const displayCalculatorResult = (result) => {
  console.log(result);
};

const calculatorWithCallback = (num1, num2, callback) => {
  let result = num1 + num2;
  // Calling our callback function
  callback(result);
};
calculatorWithCallback(1, 9, displayCalculatorResult);

Listing 9.2     JavaScript Callback

Notice that we declared two functions, one to display the output and the other to calculate it. In our calculator function, we specified two number parameters and a third callback parameter, which is where we passed the display function. So, when we call the calculator function, the display function is only executed after the calculation has completed and logs the result to the console. The key here is that the display function only runs when the calculation is complete.

9.2    JavaScript Promise

The JavaScript promise is another advanced topic, but it is effectively just another way of writing a callback function with the added advantage of returning either a success or error and letting us decide what to do in each scenario. Promises are used for situations where you need to request data from outside your app and need to wait for that data to be returned before you start processing. We can simulate this using the setTimeout() function again, which will pause our promise execution and mimic a call to an external server.

The syntax for a promise is a bit complex, but it will make sense the more you use them. In Listing 9.3, we declare a new function promise with resolve and reject parameters that we will use inside the function. We tell the function to return a resolve once the setTimeout function has completed after 5000 milliseconds (5 seconds).

const myFirstPromise = new Promise((resolve, reject) => {
  setTimeout(() => {
    resolve("The server finally sent a response!");
    reject("An error occured :(");
  }, 5000);
});

myFirstPromise
  .then((data) => {
    // resolve part
    console.log(data);
  })
  .catch((error) => {
    // reject part
    console.log(error);
  });

Listing 9.3     JavaScript Promise

Notice how there is a five-second delay before the text is logged to the console. We call the myFirstPromise function and place the then() keyword after it, which holds the function to be executed when the promise function resolves. The resolve from the promise passes the text in the resolve brackets as a parameter to the then() part, which we import using the data parameter.

Also, notice that we have a reject()in there as well, but it was not executed. Normally, you would have some logic within the promise that would determine if the resolve were called or the reject. To trigger the reject in our example, we comment out the resolve() line and run the example again like before. You should now see the text "An error occurred :(" logged to the console.

So, when using promises, just remember that promise resolve maps to the then() section and promise reject maps to the catch() section (like a TRY/CATCH block in ABAP). You can structure your success or fail logic around that.

9.3    Async and Await

The async and await keywords in JavaScript help make writing asynchronous code easier, compared to the previous promise syntax. The async keyword is used to transform a JavaScript function into a promise and replaces the new Promise syntax from Listing 9.3. This then allows you to use the await keyword within the async function, which when placed in front of a normal function will wait for that function call to finish.

In Listing 9.4, we compare a normal function versus what happens when you insert async before it. Notice how myFunction() returns the text, while myAsyncFunction() returns text wrapped in a promise because of the async keyword.

const myFunction = () => {
  return "A normal function";
};
console.log(myFunction()); // A normal function

const myAsyncFunction = async () => {
  return "A promise function"; // Promise { 'A promise function' }
};
console.log(myAsyncFunction());

Listing 9.4     async Function

Now that we know myAsyncFunction is a promise, we can rewrite our standard promise example from Listing 9.3 using the async syntax, as shown in Listing 9.5. We will also add two more calls to see how the flow works before and after the setTimeout function runs.

const myAsyncFunction = async () => {
  const myFirstPromise = new Promise((resolve, reject) => {
    setTimeout(() => {
      resolve("The server finally sent a response!");
      //   reject("An error occured :(");
    }, 5000);
  });
  // Run this first
  console.log("Let's get started!");
  // Run this second but wait to finish (5 seconds)
  console.log(await myFirstPromise);
  // Run only when the function promise above has resolved
  console.log("I had to wait for the call above to finish");
};

myAsyncFunction();

Listing 9.5     async/await Function

In Listing 9.5, we have the following text logged to the console:

Let’s get started! (Followed by a five-second pause.)
The server finally sent a response!
I had to wait for the call above to finish!

The async function acts as a wrapper for you to call other functions (including normal promises) within it, giving you better control over where one function might need to wait on another before executing. To see the benefit of the await keyword, remove it completely and see the following logged to the console:

Let’s get started! (no five-second pause).
Promise { <pending> }
I had to wait for the call above to finish!

You can clearly see where the promise (or any other function that takes time to execute) sits and how it has not been given a chance to finish before proceeding onto the next line of code, resulting in potential instability. Add the await keyword in and the correct order of events would be restored.

11    AJAX

Asynchronous JavaScript and XML (AJAX) allows you to communicate with external webservers from within your webpage using HTTP methods like GET or POST and update the DOM based on the response. AJAX revolves around the browser’s built-in XMLHttpRequest object and the more modern Fetch API, which allows you to request data outside of your webpage. You could use AJAX to call the JSON data found in Section 6 and you would receive the same JSON-formatted response.

As the name suggests, one of the benefits of AJAX is that it works asynchronously. That means when you use it to request data from a server and you do not know how long that data return will take, it will not hold up your webpage waiting for that requested data. This means your webpage can be updated in the background while still working, presenting a better user experience.

We’ll explore two key components of AJAX—the XMLHttpRequest object and the Fetch API—in the following sections.

11.1    XMLHttpRequest Object

The XMLHttpRequest object can be used to request data from resources located on an external server, depending on your server configuration. These calls are normally restricted to the same server address as the app because of a security concept called cross-origin resource sharing (CORS). For simplicity, we will assume that your local server does not allow CORS, so we will use the XMLHttpRequest object to request data from a local file stored in the same folder as our index.html and app.js files, as shown in Listing 11.1 and Listing 11.2.

13.3    Browser Storage

Modern browsers like Chrome, Firefox, and Safari all have something called browser storage, where they store certain data when you visit a webpage. Depending on the type of browser storage used, the data might be kept or deleted after you close the webpage or browser window. There are many different reasons for storing data in the browser, from identification to security and even preference data.

Your browser storage options include local storage, which persists between sessions (when you close your webpage); session storage data that expires when you close the webpage; and cookies and database storage. For simplicity, we focus on using JavaScript to save some data to the browser’s local storage and view it when we refresh the page.

Before we continue, navigate to your browser’s developer console (we use Chrome in our example) and look for the Application tab, as shown in Figure 13.4.

14    Debugging and Error Handling

Error handling in JavaScript plays a key role in development, and many techniques you use in your ABAP code can be directly translated to JavaScript, albeit with slightly different syntax. Due to JavaScript’s loose typing system, many errors will not be caught until runtime, so you should plan ahead for them.

When it comes to debugging, vanilla JavaScript does not have a tool like the much-loved ABAP debugger bundled with it. Your scenario and personal preference will dictate which tools you use. In our case, we make use of Chrome DevTools and the built-in debugger inside VS Code. There are many other debugging tools available, but these two are widely used and well documented. Alongside these tools, we also use the console.log() statement as part of your debugging strategy to log values to the console. This allows us to follow the output of our logic as the code executes to help spot any issues.

In the following sections, we’ll discuss some common types of errors and how they are viewed, before walking through the two key debugging tools and error handling in JavaScript.

14.3    Error Handling

In JavaScript, you can expect many unforeseen errors, and even though you have some great tools to debug your code, it is crucial that you implement proper error handling as well. As with all programming languages, proper error handling is key to building a stable and robust application.

Certain scenarios in ABAP can be handled by a simple IF statement if you know what errors to expect. However, there are scenarios where you need to play it safe with a TRY CATCH block. To introduce you to error handling in JavaScript, we replicate an ABAP TRY CATCH block and log a response to the console if we catch an error.

In Listing 14.5, we wrap our corrected variable assignment shown previously in Listing 14.4 in a try…catch statement:

try {
  let newCar = new car("Mercedes");
  console.log(`${newCar.make}`);
} catch {
  console.log("Something went wrong");
}

console.log(`${newaCr.make}`);
