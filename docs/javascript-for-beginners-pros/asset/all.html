CHAPTER ONE

JAVASCRIPT CONCEPTS

What is JavaScript?

JavaScript is a lightweight interpreter or just in-time compiler programming language. What then is lightweight language? Lightweight language means that it's much simpler to write code in JavaScript, unlike other programming languages like Java or C++. If you compare the syntax of JavaScript with other programming languages, JavaScript is much easier to write. And that is why it is called a lightweight language as compared to other languages like Java or C++.

What does JavaScript do?

In simple terms, JavaScript is a programming language used to make websites interactive. If you think about the basic makeup of a website, you have HTML, which describes and defines the basic content and structure of the website (HTML is the skeleton structure of a website), then you have CSS, which tells the browser how this HTML content should be displayed or determining things like colour and font (CSS is the skin that covers the skeleton structure). With just HTML and CSS, you have a website that looks good but doesn’t do much. JavaScript brings the website to life by adding functionality (JavaScript is the brain of the skeleton that allows it to think or reason, calculate, do some logical stuff, etc.).

JavaScript is responsible for elements that the user can interact with, such as drop-down menus, modal windows, and contact forms. It is also used to create things like animations, video players, and interactive maps.

JavaScript is an all-purpose programming language, meaning that it runs across the entire software stack. The most popular application of JavaScript is on the client-side (frontend), but since Node.js came on the scene, many people run JavaScript on the server-side (backend) as well. When used on the client-side, JavaScript code is read, interpreted, and executed in the user’s web browser. When used on the server-side, it is run on a remote computer. You can learn more about the difference between frontend and backend programming in our subsequent section.

JavaScript is not only used to create websites. It can also be used to build browser-based games with the help of certain frameworks or mobile apps for different operating systems. The creation of new libraries and frameworks are also making it possible to build backend programs with JavaScript, such as web apps and server apps.

Which Should You Learn First: Plain Js or frameworks & Libraries?

When deciding whether or not to learn JavaScript, what you are asking is whether or not you should learn “vanilla” JavaScript. Vanilla JavaScript means plain JavaScript without any libraries or frameworks. Let’s explore what this means in more detail now.

What are vanilla JavaScript, libraries, and frameworks?

If you research the term “vanilla JavaScript”, you might run into some confusion, however, all you need to know is that vanilla JavaScript is used to refer to a native, standards-based, non-extended JavaScript. There is no difference between vanilla JavaScript, and JavaScript, it is just there to emphasize the usage of plain JavaScript without the use of libraries and frameworks.

What are libraries and frameworks?

JavaScript libraries and frameworks both contain sets of prewritten, ready-to-use JavaScript code but they are not the same thing. You can think of a framework as your blueprint for building a website, it gives you a structure to work from and contains ready-made components and tools that helps you to build certain elements much quicker than if you were to code them from scratch. Some popular JavaScript frameworks include Angular, React, Vue, and Node.js. Frameworks also contain libraries. Libraries are smaller than frameworks and tend to be used for more specific cases.

A JavaScript library contains sets of JavaScript code that can be called upon to implement certain functions and features. Imagine you want to code a particular element into your website. You could write ten lines of JavaScript from scratch or you could take the condensed, ready-made version from your chosen JavaScript library. Some examples of JavaScript libraries include jQuery, Lodash, and Underscore.

The easiest way to understand how frameworks and libraries work together is to imagine you are building a house. The framework provides the foundation and the structure, while the library enables you to add in ready-made components (like furniture) rather than building your own afresh. You can learn more about the relationship between languages and libraries in this post explaining the main differences between JavaScript and jQuery. For now, let go back to our original question: How important is it to learn vanilla JavaScript?

Why do you need to learn vanilla JavaScript first?

When it comes to learning JavaScript, it can be tempting to skip ahead to those time-saving frameworks and libraries you just talked about and many developers do that. However, there are many compelling arguments for learning plain JavaScript first. While JavaScript frameworks may help you get the job done quicker, you can’t go far if you don’t understand the core concepts behind these frameworks. Some frontend developer describes how not learning vanilla JavaScript came back to hunt them when they started learning the JavaScript frameworks Node and Express:

“As I went to write more and more code in Node and Express, I began to get stuck at even the tiniest problems. Suddenly, I was surrounded by words like callbacks, closures, event loop, and prototype. It felt like I got a reintroduction to JavaScript, but this time, it was not a toddler playing in its cradle, it was something of a mysterious monster, challenging me on every other step for not having taken it seriously.”

“It was fun working with JavaScript framework until I got battled with stuck with parental and children inheritance which was as if I never work with JavaScript”

“JavaScript framework is the best but it is advisable to get used to the foundation of JavaScript for easy navigation”

Understanding the concept of site rendering

In layman's terms, site rendering means generating or rendering the HTML output. HTML is a markup language that web developers use to create web pages. It is said that the site rendering can happen both at the server-side and client-side levels. It is worth noting that the frontend and the client-side are synonyms. The same is true for the backend and the server-side.

Server-side rendering (backend)

Firstly, you are going to talk about server-side rendering, i.e backend development. As time pass, server-side renderings or backend web development was the de facto way to create websites and web applications. When you visit a page, send a request for the content, the server processes this request, and create a response that is sent back to the browser.

When a site renders server-side, all the processes involved in creating an HTML page that your web browser can understand are handled on a remote server hosting the website or web application. This includes querying databases for information and processing any logic that your web application requires. While the remote server is busy at work, your web browser is idle, waiting for the server to finish processing the request and sending a response. When the response is received, web browsers interpret it and display the content on the screen.

Client-side rendering (frontend)

In more modern days, a new form of site rendering emerged called client-side rendering or frontend development. With client-side rendering, the rendering of the content on the website happens in your computer instead of the remote web server using the de facto language of the web which is JavaScript.

In practical terms, it means that a server is only needed to serve the raw web application, and the browser will be in charge of rendering this application in its final form which is mainly on the HTML language end. It also means that some of the logic involved in creating the web page, especially the one in charge of dealing with how things are presented to the user on the screen (called presentation logic) are handled on the client-side. Client-side rendering became popular with the advent of JavaScript libraries such as Angular, React, and Vue.

Assuming you decide to start a business of your own, a bakery or a tailor shop for instance. You need a professional website to present your company to your customers and tell them where you are located. Maybe you will include a few photos and some information about your products. All you need are frontend technologies to build your website.

What is frontend development?

Now that you understand the different types of site rendering methods, it is easier to understand that front-end development is the art of creating the site, and web applications that render on the client-side.

Technologies used for frontend development

There are many different types of technologies and stacks, most frontend web developers use HTML, CSS, and JavaScript, the de facto building blocks of the web, and the client-side frameworks such as Angular, React, Stencil and Vue. Not everything happens on the front end, though, client-side rendered applications still rely on services and APIs that run on back-end remote servers or the cloud.
