## REST APIs 简介

REST 是一种处理客户端-服务器关系的架构风格，目的是通过使用可重用组件追求速度和性能。REST 作为一种技术通过 Roy Fielding 的论文（https://www.ics.edu/~fielding/dissertation/top.htm）引入世界。现在通常认为优于 SOAP（简单对象访问协议），因为 REST 使用的带宽更少，对于互联网使用来说更简单灵活。

### 什么是 REST API？

REST API 是一种易于访问 Web 服务的方法，无需额外的处理。每当调用 RESTful API 时，服务器将向客户端传输请求资源状态的表示。事实上，我们几乎每天都在使用它！如果你尝试在 YouTube 上寻找视频。你会在搜索框中输入“biking”，按回车，然后你会看到一个列表。从概念上说，REST API 的工作方式就是这样！你搜索某些内容，然后从你请求的服务返回结果列表。API 是应用程序编程接口。它是一组允许程序相互通信的规则集。开发者在服务器上创建 API 并允许客户端与其通信。REST 决定了 API 的外观。它是开发者在创建 API 时遵循的规则。其中一个规则规定，当你链接到特定 URL 时，你应该能够获取数据数据（资源）。每个 URL 被称为请求，而返回给你的数据被称为一个

### RESTful 架构

- **无状态**：意味着服务器不存储客户端数据，会话存储在客户端（通常会话存储中）。

- **客户端<->服务器**：前端（客户端）和后端（服务器）之间存在关注分离。它们独立运行且都是可替换的。

- **缓存**：来自服务器的数据可以在客户端缓存，这可以提高性能。

- **URL 组合**：我们使用标准的基 URL 组合。例如，`GET` 请求将产生数据库中的所有城市，而对 `/cities/seattle` 请求将渲染 ID 为 Seattle 的城市。同样，REST 利用标准方法如 `DELETE` 和 `POST` 来执行操作。

#### REST 的运行

让我们更仔细地查看它是如何执行的！我们的请求通过 HTTP 以 Web URL 的形式从客户端发送到服务器。使用 `GET`、`POST`、`PUT` 或 `DELETE`。然后从服务器返回响应，可以是任何内容如 HTML、XML、图像或 JSON。JSON 是目前最流行的格式，所以我们将使用它作为示例。

HTTP 有五种在 REST 架构中常用的方法：POST、`GET`、`PUT`、`PATCH` 和 `DELETE`。事实上，它们分别对应创建、读取、更新和删除 (CRUD) 操作。还应该注意，还有其他较不常用的方法，如 `OPTIONS` 和 `HEAD`。
