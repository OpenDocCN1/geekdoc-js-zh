## 第 1 章：Python 编码通用概念

在我们正式进入书籍之前，这些是你应该意识到的编码通用概念；这些概念会让你的生活变得更轻松。

### 显式代码

虽然你可以用 Python 许多许多奇奇怪妙的事情，但最好保持简单直接和显式。

#### 一个糟糕的示例：

```python
def make_complex(*args):
    x, y = args
    return dict(**locals())
```

#### 一个良好的示例：

```python
def make_complex(x, y):
    return {'x': x, 'y': y}
```

比较这些示例；在后者的代码示例中，我们从调用者那里显式地接收了 `x` 和 `y`，返回值是一个显式的字典。

编写这段代码的开发者只需看第一行和最后一行就知道要做什么；糟糕的示例并非如此。

### 一行一个语句

虽然允许复合语句（如列表推导式），并且在很多情况下是受推崇的，但在行内放置两个互不关联的语句并不是良好做法。

#### 一个糟糕的示例：

```python
print 'one'; print 'two'

if x == 1: print 'one'

if <complex comparison> and <other comparison>:
    # do something
```

#### 一个良好的示例：

```python
print 'one'
print 'two'

if x == 1:
    print 'one'

cond1 = <complex comparison>
cond2 = <other comparison>
if cond1 and cond2:
    # do something
```

### 返回值

当你获得一个复杂度不断增加的函数时，在函数体中使用 `return` 语句并不罕见。然而，如果你想保持清晰的意图和良好的可读性，你应该尽量不要从函数的多个点返回值。

当在函数内部返回值时，有两种情况：来自正常处理的返回结果，以及指示输入参数错误或由于某种原因函数无法完成计算的错误。

如果你不想在后一种情况下抛出异常，那么可能需要返回某些值（如 `False` 或 `None`）作为函数未能正常执行的指示。在这样的情况下，最佳实践是一旦注意到错误的上下文就立即返回。

这将有助于整洁函数结构，因为错误返回之后的所有代码都假设条件已经满足，从而可以计算主函数的结果。因此，有时确实需要多个这样的 `return` 语句。

尽管如此，如果一个函数包含了多个不同的可以走的路径，那么调试结果可能会变得棘手，因此最好只维护一条路径。这有助于推导出代码路径。

#### 例如：

```python
def complex_function(c, b, a):
    if not c:
        return None # 抛出异常
        异常可能更好
    if not b:
        return None # 抛出异常
        异常可能更好
    # 尝试从 c, b 和 a 制作 x 的一些复杂代码
    # 如果成功，尽量不要返回 x
    if not x:
        # 备选方案计算 x
        return x # 一个出口点对于
        值 x 将很有帮助
```

这些是编写 Python 代码的基本建议，如果你希望你的代码更加有效、高效且具有可读性，你应该遵循这些建议。

- 你的代码编写方式不应对其他 Python 实现产生不利影响，例如 `IronPython`、`Jython`、`PyPy`、`Psyco` 和 `Cython`。

例如，你不应该永远依赖于 `CPython` 中高效的字符串拼接，其形式为 `a=a+b` 或 `a+=b`。这是一种相当脆弱的优化，尽管它在 `CPython` 中效率极高，但因为它对所有类型都不生效，而且在任何不使用引用计数的 Python 实现中都不存在。

相反，每当你使用对性能敏感的库部分时，你应该使用`.join()`形式。这可以确保拼接在所有不同的 Python 实现中都是线性耗时的。

- 永远不要使用等值运算符来与`None`等单例进行比较。相反，请使用`is`或`is not`。

你还应该警惕在应该使用`if x is not None`的地方使用`if x`。一个例子是，当你正在测试一个默认值为`None`的参数或变量是否真的被设置了不同的值时。另一个值可能是一个在布尔上下文中为假的类型。

- 与其使用`not is`运算符，你应该使用`is not`。虽然它们在功能上是等等的，但前者的可读性较低，因此后者更受青睐。例如：

#### 推荐用法：

```python
if foo is not None:
```

#### 不要这样用：

```python
if not foo is None
```

- 当你使用富备比较（`rich comparison`）实现排序操作时，你应该实现所有的 6 个操作，而不是依赖其他代码来执行比较。这些操作是`__eq__`、`__lt__`、`__ne__`、`__ge__`、`__gt__`、`__le__`

为了减少工作量一个特定的装饰器可以帮助生成缺失的比较方法。该装饰器是`functools.total_ordering()`。

风格指南指出，Python 假设反射性规则。因此，Python 解释器可能会交换`y > x`和`x < y`的顺序，或者可能会交换`y >= x`和`x <= y`。

你可能还会发现参数`x == y`被交换成了`x != y`。`min()`和`sort()`操作肯定会使用`<`运算符，而`max()`函数将使用`>`运算符。但是作为最佳实践指南，你应该使用所有的操作，以防混淆。

- 与其使用将 `lambda` 表达式绑定到标识符的赋值语句，不如使用`def`语句

#### 良好的示例：

```python
def f(x): return 2*x
```

#### 糟糕的示例：

```python
f = lambda x: 2*x
```

第一个示例显示，给函数对象的名称是 `'f'` 而不是集体的 `<lambda>`。这对于字符串表示以及回溯轨迹（`tracebacks`）最有用，而通过使用赋值语句，你放弃了 `lambda` 表达式相比`def`语句所提供的唯一优势——即它可能被嵌入到更大的语句中。

当你想要派生异常时，请使用`Exception`而不是`BaseException`。从后者的继承是留给那些捕获它们时几乎总是错误的异常的。

在设计异常层次结构时，应根据捕获异常可能需要的性质来构建，而不是根据异常抛出的位置。始终回答一个问题——“出什么问题了？”而不是仅仅说某事出错了。使用类命名的约定，但为产生错误的异常类添加“`Error`” 后缀。

对于不是错误且用作流程控制或其他信号形式的异常，没有需要添加特殊后缀。

- 当你使用异常链（`exception chaining`）时，仅在需要的地方使用。

当你故意替换内部异常时，请确保将正确的细节转移到较新的异常中。示例包括：在将`KeyError`转换为`AttributeError`时确保属性名称被保留，或者在将原始异常文本嵌入到新异常的消息中。

- 当你使用 Python 2 并抛出异常时，始终使用`ValueError('message')`而不是`raise ValueError 'message'`

这是因为第二个示例在 Python 3 中既不是有效的也不是合法的语法。此外，使用包含的括号意味着，当你在添加字符串格式化或异常参数过长时，不需要在行末尾使用续行符。

- 当你捕获异常时，尽可能在任何地方提到具体的异常，而不是使用裸露`except:`子句

#### 例如：

```python
try:
    import platform_specific_module
except ImportError:
    platform_specific_module = None
```

`KeyboardInterrupt`和`SystemExit`异常会被裸露`except:`子句捕获，这使得使用 CTRL+C 中断程序变得困难得多，而且它们还会掩盖可能存在的其他问题。

如果你想要捕获程序中信号错误的每个异常，请使用`except Exception:`。一个通用规则是仅在以下两种情况使用裸露`except:`子句：

1. 如果回溯轨迹（`traceback`）是由异常处理器打印的；这样用户就能感知任何错误。

2. 如果需要清理工作，但代码允许通过`raise`让异常向上传播。此此更有效的方法是使用`try...finally`。

当你将捕获的异常绑定到名称时，使用 Python 2.6 的显式绑定语法：

```python
except Exception as e:
```

（注：原文示例代码不完整，此处根据上下文补全了常见的`as e`语法）

- 当你比较对象类型时，请使用`isinstance()`而不是直接比较

#### 良好的示例：

```python
if isinstance(obj, int):
```

#### 糟糕的示例：

```python
if type(obj) is type(l):
```

当你检查一个对象是否为字符串时，请记住它也可能是 Unicode 字符串。在 Python 2.0 中，Unicode 和 `str` 共享一个名为`basestring`的基类，因此你可以这样做：

```python
if isinstance(obj, basestring):
```

然而，在 Python 3 中，你找不到`basestring`或`Unicode`，只有`str`和`bytes`对象不再是字符串，它们现在是整数序列。

对于序列（元组、列表、字符串等）——请利用“空序列为假”这一特性。

#### 良好的示例：

```python
if not seq:
    if seq:
```

#### 糟糕的示例：

```python
if len(seq):
```

```python
if not len(seq):
```

不要包含任何需要大量尾部空格的字符串字面量，因为这些空格是无法的，且某些文本编辑器会删除它们。

不要使用`==`来比较布尔值`True`或`False`：

#### 良好的示例：

```python
if greeting:
```

#### 糟糕的示例：

```python
if greeting == True:
```

#### 更糟糕的示例：

```python
if greeting is True:
```

## 第 3 章：代码布局

最显易的开始点是如何布局你的代码。我将为你提供代码布局的最佳实践指南，以及关于如何这样做以及如何避免的示例：

### 缩进与对齐

每个缩进层级应该是 4 个空格。

当你使用延续行时，它们应该使用以下两种方法之一对折后的元素对齐：

- 使用 Python 在大括号、括号和圆括号内隐式连接行的垂直方式

- 使用悬挂缩进（`hanging indents`）

当你使用悬挂缩进时，请考虑第一行不应该有任何参数，并且为了标记延续行，必须使用缩进。

考虑以下示例：

#### 正确的方法：

```python
### 与起始分隔符对齐。
foo = long_function_name(var_four,
    var_three,
    var_two,
    var_one)

# 并包含了更多的缩进，以便与代码的其他部分区分来

def long_function_name(
    var_four, var_three, var_two,
    var_one):
    print(var_four)
```

#### 应使用悬挂缩进来增加层级。

```python
foo = long_function_name(
    var_four, var_three,
    var_two, var_one)
```

#### 错误的方法：

#### 不使用垂直对齐时，第一行不允许出现参数。

```python
foo = long_function_name(var_four, var_three, var_two, var_one)
```

#### 需要更多的缩进，因为当前的缩进与其余部分无法区分。

```python
def long_function_name(
    var_four, var_three, var_two,
    var_one):
    print(var_four)
```

对于延续行，4空格缩进的规则是可选的：

#### 悬挂缩进*可以*缩进多于或少于4个空格。

```python
foo = long_function_name(
    var_four, var_three,
    var_two, var_one)
```

当你使用带有跨越多行的长条件的`if`语句时，请注意条件语句中的其余行可以轻松创建 4 个空格的自然缩进——使用一个两个字符的关键字（例如`if`）加上一个空格和一个左括号）。然而，在视觉上，这可能看起来与`if`语句内部的缩进代码不兼容，因为内部代码已经有了 4 个空格的缩进。关于是否要区分这些条件行与嵌套内部的代码，并没有真正的标准，但你可以使用几种可接受的选项，包括但不限于：

```python
### 没有使用额外的缩进。

if (this_is_one_thing and
    that_is_something_else):
    do_this()
```

```python
### 添加注释，这将为支持语法高亮的编辑器提供一些帮助。

if (this_is_one_thing and
    that_is_something_else):
    # 因为两个条件都为真，我们可以进行调整。
    do_this()
```

#### 为条件的延续行添加更多缩进。

现在，当你有一个多行结构时，闭合的大括号、括号或`can`行可以对齐到两个位置之一——与列表末行非空格的起始字符对齐：

```python
my_list = [
    6, 5, 4,
    3, 2, 1,
]

result = a_function_that_will_take_arguments(
    'f', 'e', 'd',
    'c', 'b', 'a'
)
```

或者它可以与多行结构中第一行的起始字符对齐：

```python
my_list = [
    6, 5, 4,
    3, 2, 1,
]

result = a_function_that_will_take_arguments(
    'f', 'e', 'd',
    'c', 'b', 'a'
)
```

# 第 5 章：注释

由于你已经具有一些 Python 编程经验，你会知道注释在程序运行时是不可见的。注释的作用是帮助代码编写者和其他阅读代码的人理解他们做了什么以及为什么要这样做。现在，有些人认为，正因为注释是不可见的，所以没必要写它们；而另一些人写的注释毫无意义且与他们的代码矛盾。我必须告诉你，在这两者之间，写一个自相矛盾的注释比完全不写要糟糕得多，因此，每当你对代码进行更改时，都必须确保更新了相应的注释。

当你写注释时，确保它是一个完整的句子并有正确的结束句号。就像你写任何内容一样，你的注释（无论是句子还是短语）必须以大写字母开头。该规则的唯一例外是它是以小写字母开头的标识符——这里的黄金法则是：你**永远不要**改变标识符的大小写！

如果你使用的是短注释，可以省略末尾的句号。如果你在写块注释，这些注释通常由至少一个段落组成，有时更多，每一段都由完整的句子组成。这些句子中的每一个都必须有一个句号。每个句号后面应该有 2 个空格，并且所有注释都应该用英文编写。唯一的例外是你 200% 确定你的代码永远不会被不懂或不读你所在语言的人阅读。

## 块注释

块注释通常适用于其后的部分或全部代码。注释的缩进方式与它所指的代码完全相同，每个块的每一行都必须以 `#` 和一个空格开头。唯一的例外是你注释内部使用了缩进文本。每个块注释中的所有段落都必须用包含一个 `#` 的行隔开。

### 行内注释

这些注释应尽可能少使用。回顾一下，行内注释是放置在语句同一行的注释。行内注释与语句之间至少要有两个空格，并且它们必须以一个 `#` 和一个空格开头。

诚实地说，你应该避免使用行内注释，因为它们并不是必需的，并且会引起不必要的干扰。

例如，你不应该这样做：

```python
x = x + 1    # Increment x
```

然而，有时，这可能是有用的：

```python
x = x + 1 # Compensate
# for the border
```

# 第 6 章：规范

为了让你的 Python 代码变得好得多，请遵循这些规范：

查看你的变量是否等于一个常量。没有必要对值与 `0`、`None` 或 `True` 进行显式比较；相反，你可以将其加入 `if` 语句中。看以下示例：

### 错误的示例

```python
if attr == True:
    print 'True!'
```

```python
if attr == None:
    print 'attr is None!'
```

### 好的示例

```python
# 只看值即可
if attr:
    print 'attr is the best!'
```

```python
# 或者检查相反的情况是什么
if not attr:
    print 'attr is the worst!'
```

```python
# 或者，由于 None 被视为假，
# 确保你对它进行了显式检查
if attr is None:
    print 'attr is None!'
```

### 如何访问字典元素

不要使用 `dict.has_key()` 方法，请使用 `x in d` 语法或使用 `dict.get()` 来传递默认参数。

### 错误的示例

```python
d = {'hello': 'world'}
if d.has_key('hello'):
    print d['hello']      # 输出 'world'
else:
    print 'the_default_value'
```

### 好的示例

```python
d = {'hello': 'world'}
print d.get('hello', 'default_value')   # 输出 'world'
print d.get('thingy', 'default_value')  # 输出 'default_value'
```

```python
# 或者
if 'hello' in d:
    print d['hello']
```

### 简短操作列表

在操作列表时，你不需要长篇大论；当你想要对列表执行操作时，使用列表推导式或 `filter()` 或 `map()` 函数来使用简洁的语法。

### 错误的示例

```python
# 过滤所有大于 4 的元素
a = [5, 4, 3]
b = []
for i in a:
    if i > 4:
        b.append(i)
```

### 好的示例

```python
a = [5, 4, 3]
b = [i for i in a if i > 4]
```

```python
# 或者：
b = filter(lambda x: x > 4, a)
```

### 另一个错误的示例

```python
# 给列表中的所有成员加 3。
a = [5, 4, 3]
# 然后对每个元素加 3（但这里缺少了具体操作）
```

### 另一个好的示例

```python
# 给列表中的所有成员加 3。
a = [i + 3 for i in [5, 4, 3]]
```

### 从文件读取

当你想要从文件读取时，最好使用 `with` 语句，因为它能确保文件被关闭。

### 错误的示例

```python
f = open('file.txt')
for line in f:
    print line
f.close()
```

# 第 7 章：方法和函数参数

对于任何实例方法的第一个参数，始终使用 `self`；对于任何类方法的第一个参数，始终使用 `cls`。

如果函数参数的名称与某个保留关键字相同，那么最好在末尾添加一个下划线，而不是使用损坏的拼写或缩写。因此，你应该使用 `class_` 而不是 `cls`。也许比引起冲突更好的方法是使用同义词。

## 函数参数

你通过以下 4 种方式向函数传递参数：

- **位置参数（Positional）** – 这些是强制性的，并且不包含任何默认值。位置参数是最简单的参数形式，用于那些是函数含义完整组成部分的参数；它们也有一个自然的顺序，因此，在下面的示例中，函数用户应该很容易记住那 2 个函数需要 2 个参数，并且应该记住顺序：

```python
Send(message, recipient)
point(x, y)
```

在两种情况下，你都可以在调用函数时使用参数名称，通过这样做可以改变参数的顺序。例如你可以调用 `send(recipient='world', message='Hello')` 和 `point(y=2, x=1)`。但是，正如你从此可以看到的那样，它并不十分可读，而且比这里我们需要的词要多得多。与那个版本相比，更直接的方式是 `send('Hello', 'World')` 以及 `point(1, 2)` – 你立刻就能看到可读性的差异了。

## 关键字参数

包含默认值并且它们不是强制性的。关键字参数有时用于可选的参数。当你发送给功能时，如果一个函数至少含有 20 个或更多位置性参数，它就不容易记住。使用具有默认值的关键字参数更有帮助。通过例如，您可以定义完整的函数，如发送消息到 `cc=None`，`bcc=None`，该用法可选择并且两者都有值为 `None`，如果没有给予另一个值。有一些方法在 Python 中使用一个关键字参数来调用一个函数，例如，你可以遵循与上面提到的位置参数定义相同的方式，并显式命名这些参数；例如，`send('Hello', 'World', 'galactus@example.com', 'god@example.com')`。这里是一个 `carbon copy of message` 的发送给 `al`，`cc` 给 `bob`，`bcc` 给 `god`。你也可以以不同的顺序命名这些参数，例如：`send('Hello Again', 'World', bcc='god@example.com', cc='bob@example.com')`。

除非您有一个非常好的理由不跟随正确的语法，否则请遵循这些示例。以上两个示例是最好的做法，应避免复杂或不可读的写法。

## 任意参数列表

这是通过传递给函数作为下一种方式。有时候一个函数的意图是更好地表达为具有一个可变数量的位置参数，这个数量可以被扩展。在这种情况下，你最好使用带 `*` 的构造来定义它，这会收集所有的额外参数到一个元组中。例如，`send(message, *recipients)`，然后你可以在调用时列出所有的接收者作为单独的参数，如 `send('Hello', 'galactus@example.com', 'god@example.com')`。

对于更复杂的情况，你可以使用 `**` 来处理关键字参数。

再次说明，用于功能的命名规范同样适用——采用小写英文字母并夹杂下划线。如果您想要一个实例变量或是非公开的方法，您应该在字首添加一个下划线。为了防止名称因为超类而互相冲突，头部两个下划线应被视为一种约定，并且会有个别机制针对此问题。当这些特殊情况出现在簿记上的时候，该属性通常会带有先导类的名词前缀。例如，`Foo` 包含一个属性称为 `_pos`，这可以访问通过 `Foo._pos`。作为一条基本准则，你通常不得让领先的私有属性被外部直接访问。
